## 我们要做的程序

我们要建设的是带界面的具身智能数据管线工作台。它先组织 Host、机器人计算单元、相机与遥操作服务，让用户完成环境准备、启用遥操作和回合保存；再通过独立阶段按钮运行检查、可选增强、转换、训练、仿真评估与部署。用户也可导入公开或购买数据，从来源适配进入共同下游。首期单人、单机器人，允许把满足条件的阶段自动串联。

统一的是工作流程和产物管理；更换机器人时，通过设备、遥操作、记录、仿真与部署适配器处理厂家差异。跨本体动作迁移可能还需模型、数据和算法工作。具体研究见 [三家厂商适配调研](product/03_三家厂商与更换本体适配调研.md)。

现有 CLI 具备原始 Unitree JSON 检查、28 维双臂双手数值导出、官方转换命令规划、LeRobot 元数据检查、真实开源数据的小规模行为克隆和 G1 MuJoCo 可视化。这些是技术验证模块，尚未组成图形工作台；当前没有真机控制入口，也未运行官方 LeRobot 完整转换环境。本轮先交付需求与调研，后续分阶段实现。

## 今天能够证明什么

- 官方代码的设备职责、DDS 主题、原始 JSON 和转换字段已逐项核查，保留了版本与源码快照。
- 使用真实官方开源 G1 + Dex3 数据进行数值训练，按完整 episode 划分训练、验证和测试。
- 在 G1 43 关节模型中显示离线预测，并用固定机身的 MuJoCo 动力学做短时闭环数值检查。
- 这些实验能展示数据如何进入程序、如何训练和如何评价；任务成功率尚未测量。

## 今天不能声称什么

不能声称已经自主搬箱、稳定抱箱行走、完成 sim-to-real，或已经验证 Apple Vision Pro 真机采集。我们没有真实设备，开源烤面包任务也不是搬箱数据。固定机身模型不含行走和平衡；视频中的烤面包场景没有重建。测试回合属于同一任务，不能代表跨场景泛化。

## 保留的工程问题

1. 43 DoF 很可能对应 29 本体加双手 14，但需要订单和手部照片确认。
2. 要学习“走路”，必须明确定义输出是底盘速度指令、上层步态目标，还是腿部关节目标；三者对应完全不同的数据契约。
3. 普通 `Unitree_G1_Dex3` 转换只提取双臂和双手，即使原始 JSON 有 `body` 字段也不会自动变成移动操作数据。
4. 官方全身数据是另一种多字段 schema，手型、坐标系和动作语义需要专门适配。不能将重复的腿腰表示简单拼接求总维度。
5. 官方 README 可能保留旧示例。已发现烤面包数据卡正文仍展示 v2.0，而本次固定 revision 的 `meta/info.json` 是 v3.0。程序按实际元数据和路径模板读取。
