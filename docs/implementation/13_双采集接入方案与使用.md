# 真机与仿真采集接入

日期：2026-10-31。目标：从工作台启动已配置的采集服务，控制随动与逐回合录制，确认保存后自动入库并排队质检。

## 用户路径

选择真机／仿真配置 → 连接采集执行器并预检 → 启动服务 → 现场连接头显并启用随动 → 开始录制 → 停止并保存 → 自动传输、入库、质检。保存后可继续下一回合；传输和质检优先让出录制资源。

首次部署由部署者配置执行机的 Python、固定版本仓库、相机或仿真服务及输出目录。日常使用者只选择配置并操作阶段按钮。服务启动包含上游控制器初始化，界面明确说明，不称为只读连接。

## 执行与状态

- 工作台保持本机 HTTP；本地或 SSH 标准输入输出连接采集 Agent，不在局域网裸露控制 HTTP，不接受网页传入任意 shell 命令。
- Agent 读取执行机上的受信任 JSON 配置，启动固定参数的 Unitree 程序及相机／仿真依赖。仅管理本次启动的进程；明确复用的服务只探测、不终止。
- 固定 `xr_teleoperate@817fb00c63cde15e5f24a0f8fa08e1e33ed89d3b` 的主程序及 EpisodeWriter 哈希，使用运行时包装，不修改上游仓库文件。把 `--ipc` 接口接到受认证的本机桥，读取实际 get_state()；不依赖终端模拟按键。
- START、READY、RECORD_RUNNING 来自上游实际状态。开始／停止录制分别是幂等意图；发送一次 toggle 后等待观测，超时显示未知，不重复翻转。
- 包装 EpisodeWriter，在写入队列结束、JSON 关闭并检查媒体之后发出原子完成事件。目录出现、ACK、文件大小暂时不变均不作为保存完成证明。写入错误或缺失媒体不发出成功完成事件。
- XR 新鲜度、物理控制权和本体动作范围无法由上述状态单独证明，显示待现场核对。当前先支持 G1_29 + Dex3 上肢数据；不据此宣称完整携箱行走已验收。
- 仿真使用 `--sim`、DDS 域 1 和 loopback；真机使用域 0 与明确网卡。两个配置不能同时运行，切换前须结束本次会话。

## 数据交接

每个完成回合有会话 ID、回合 ID、来源模式、任务快照、完成事件和文件校验。Agent 生成 ZIP_STORED 归档，工作台按有界数据块传输，安全解包后登记受管资产；同一事件重试不重复入库或重复排质检。录制未完成的目录不能导入。登记后逐回合加入现有质检队列，保留源与作业关系，失败显示具体原因并允许重试。

工作台重启不盲目恢复控制。采集端连接丢失显示状态未知；重新连接后先对账。关闭服务走停止录制、等待保存和上游正常退出，超时才清理本次持有的进程。普通“结束服务”不标为硬件急停。

## 验证边界

需要真实服务启动、录制状态变化、保存事件、传输、入库与后台 worker 的集成测试；另外覆盖重复点击、响应丢失、缺图、保存失败、重连、退出和 Windows 路径。测试适配器只能显式选择并标为合成，不代替真机或 GPU 场景验收。

本轮未获得实际工作站 SSH、环境路径和设备配置。软件接线、合成采集链路、界面操作和独立安装包已验证，结果见文末；实际设备与 GPU 联调结论另行记录。

## 日常操作

1. 在“当前任务”点“开始采集”，或从左侧进入“采集数据”。
2. 没有设备时，点“没有设备？用合成数据试运行”。它会配置并启动本地试运行进程，不需要填写 SSH 或 Python 路径。
3. 服务就绪后点“启用随动”，再点“开始录制”。结束时点“停止并保存回合”。试运行每回合最长约 30 秒后自动保存。
4. 回合保存后自动接收、入库和排队检查；列表分别显示各状态。可直接标记任务成功、失败、中断或待判断，不改写原始数据。
5. 可继续录制下一回合。结束本次采集时点“结束采集服务”；录制/保存过程中不会把该操作当成停止回合。
6. 到“当前任务”点“整理数据”。采用推荐的成功回合，或手动调整。点“核对这些数据”时工作台自动保存并安排默认划分，最后点“确认使用这些数据”开始整理。

推荐只包含当前任务中结构检查通过、人工已标记成功的回合，不把未知任务或待判断回合自动当成功示范。试运行数据始终标为合成，不能用来证明策略完成搬箱。

## 执行机首次部署

工作台和采集 Agent 使用 Python 3.11+ 标准库。厂商的遥操作/Isaac 环境单独保留，配置中用 `python` 指向其解释器；不要求把 Isaac 安装到工作台环境。若厂商 Python 版本低于 3.11，需要在目标机另行验证启动包装器兼容性，本机未作该组合验收。

在 Linux Host 的独立环境中安装本工作台 wheel 或源码：

```bash
python3 -m venv /opt/robot/agent-env
/opt/robot/agent-env/bin/python -m pip install /path/to/robot_data_pipeline-0.4.0-py3-none-any.whl
```

把 [真机配置示例](../../examples/capture/real/capture-profile.json) 或 [仿真配置示例](../../examples/capture/simulation/capture-profile.json) 复制到对应配置目录，修改实际仓库、解释器、网卡、相机地址和输出目录。输出目录需事先创建。配置是执行机上的受信任文件，其中服务命令由部署者核对；浏览器不能直接提交命令数组。

真机示例把 PC2 相机服务作为受控 SSH 子服务。PC2 的 `agent_python` 环境也需要安装本工作台轻量包，`argv` 则指向相机依赖环境。已经由厂商启动的相机可明确设为 `manage: "reuse"`，删除不需要的启动参数并保留探测地址；本会话不会结束这类服务。探测成功只表示服务端口可达，不代表已验证视频新鲜度或标定。

仿真示例使用固定 Unitree Isaac Lab 仓库配合 `--sim`，限定仿真在 Host 本机、`lo` 网卡和 DDS 域 1；与真机域 0 分开。示例中的场景是官方红块取放任务，只说明启动接线，不是完整搬箱场景。搬箱任务需准备并验证相应场景，再替换服务命令的 `--task`。不自动下载模型、安装 GPU 栈或租赁资源。

在界面“设备设置”中选择 SSH 工作站，填写已配置的 SSH 别名、Agent Python 完整路径和配置目录，保存并连接预检。SSH 使用 `BatchMode=yes`，沿用本机 SSH 配置和主机校验；界面不接收密码，也不关闭主机验证。也可由工作台直接连接同机 Agent，但 Unitree 实际适配器仍要求 Linux Host。

执行器配置固定 `xr_teleoperate@817fb00c63cde15e5f24a0f8fa08e1e33ed89d3b`；主程序和 EpisodeWriter 均按官方原始字节 SHA-256 校验。首次核查发现旧证据快照与原文件只有尾部换行差异，因此实际校验值采用重新下载的官方原始文件，记录见 `evidence/capture_bridge_2026-10-31/source_manifest.json`。

## 文件和恢复

- 官方原始回合保留在执行机 `output_root/capture-<会话ID>/raw/`；会话元数据、服务日志、保存完成事件及快照清单保留在同一会话目录。
- 包装器在加入写入队列时附加 Host 单调时钟时间，并标明其语义。它不是各相机/关节的硬件同步时间。
- 自动接收采用有界传输，单回合最多 4 GiB / 100000 文件，单个 JSON 最多 20 MiB；普通手工导入仍保留旧上限。超过上限明确报错并保留源回合，不能以此宣称无限流式数据仓库。
- 接收失败可“重试接收”；完成事件和确定性资产 ID 防止重复登记。工作台重启会把未完成接收显示为可重试状态，不自动开始新的机器人动作。
- 如果 ACK 丢失，先通过真实状态核对，不重发 toggle；确认目标状态后保留对账记录。
- “清理本次失败进程”仅在失败或状态未知时显示，需现场确认；它只结束本次持有的进程，不代表硬件急停或控制释放已验收。
- 当前结构质检仍针对项目支持的 28 维上肢记录。其他额外部位会保留原始文件，但不据此承诺已支持全身训练。
