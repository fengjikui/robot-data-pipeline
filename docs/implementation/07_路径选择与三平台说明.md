# 路径选择与三平台说明

版本：v0.1.1。当前界面唯一的路径输入是“数据目录”，已增加可点击的目录浏览器。任务描述、资产名称、标签等内容保持文本输入。工作区仍由启动参数指定，作业输出和日志目录由系统管理，本次没有增加工作区热切换。

## 使用方法

1. 点击“导入本地目录”。
2. 点击路径框旁的“选择文件夹…”。
3. 从主目录、下载、文档或磁盘/挂载入口进入；点击子目录继续浏览，使用“上一级”返回，也可筛选当前层的文件夹名称。
4. 到达数据所在目录后点击“使用此目录”，系统把绝对路径填回表单。取消或按Esc不会修改原路径，其他已填写内容保留。
5. 核对来源、任务、本体与许可，再点击“复制并登记资产”。选择路径本身不会导入或修改数据。

原有手动粘贴路径保留；选择器顶部也可输入完整目录路径并点击“前往”。目录列表按层读取，每页100项，可以继续显示；单层扫描超过20000项时会提示缩小目录范围。

## 平台适配

| 平台 | 目录与磁盘入口 | 路径处理 |
| --- | --- | --- |
| Windows | 主目录、已存在的下载/文档目录、系统实际盘符 | 用Win32 `GetLogicalDrives`枚举盘符，支持中文、空格和Windows本机路径 |
| macOS | 主目录、下载/文档、根目录、`/Volumes` | 使用本机路径及Unicode文件名 |
| Linux | 主目录、已存在的下载/文档、根目录、已存在的`/mnt`与`/media` | 使用本机路径，不依赖桌面环境、Tk、Zenity或KDialog |

这是**工作台内的目录浏览器**，三平台使用相同交互。浏览的是运行服务那台电脑的目录，而非另一台客户端的文件系统，也不是文件上传控件。浏览器的普通文件输入不会提供真实绝对路径，不能把`C:\fakepath`交给本机目录导入器，参见[MDN文件输入说明](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/input/file#value)。

未安装桌面文件管理器的Linux环境也可使用同一选择器。当前服务仍只监听本机回环地址；本功能不改变联网或多人部署范围。

## 失败与取消

- 不存在、不可读或磁盘不可用时显示可读提示，不自动创建目录、不弹出权限提升，也不改动数据。
- 链接、junction和其他重解析点显示为不可选择，与现有导入规则保持一致。
- 输入另一个系统的路径时，仍按服务所在操作系统校验；不会把Windows盘符猜测成Linux目录。
- 返回上级、切换常用目录或取消后，迟到的请求结果不会回填其他输入框。
- 目录选择请求复用Host/Origin与会话token保护，不提供任意命令或文件内容读取接口。

## 实现与验证

- `robot_pipeline/workbench/file_browser.py`：只读的本机目录枚举、分页、筛选与平台磁盘入口。
- `POST /api/paths/list`：需要当前工作台令牌，GET不能列出目录。
- `static/path-picker.js`：目录选择组件；新的目录输入可使用`data-path-input="目标输入框ID"`接入同一组件，继续复用服务端路径校验。
- `tests/test_workbench_file_browser.py`：真实文件系统测试，覆盖中文与空格、根目录/父目录、分页、空目录、权限错误、符号链接、Windows盘符和选择后导入，以及跨站拒绝。
- wheel安装烟测新增选择器JS响应类型与“浏览选中目录 → 导入 → worker质检/导出”验证。

开发机已通过浏览器操作验证选择、取消、筛选、上级导航及实际入库/导出。三平台的原生测试结果、具体commit和跳过项应以本版本的CI与发布记录为准；开发机点击不外推为Windows/Linux原生浏览器实测。

从旧安装包升级时需安装v0.1.1或更新源码，按原指南停止旧服务后再启动，并刷新页面。仅刷新旧后端页面不足以接入新目录接口。
