# 回合级数据准备工作台：方案与本轮实现边界

日期：2026-10-31。依据：会后 PRD 共创和三位 agent 的产品、后端、UX 独立审查。

## 方案结论

首个实现迭代交付一条连续软件路径：**已有数据入库 → 选回合/预览/标记 → 非破坏切段 → 组合与划分 → 确认清单 → 构建含媒体的准备包 → 实际项目契约读取验证与产物追踪。**

这是第一阶段中的数据准备里程碑。第一阶段总体终点仍为真实训练与匹配场景闭环仿真；真机部署另行验收。本轮不将项目读取、自有 JSONL 或模拟状态当成官方训练器、真实采集或闭环仿真已经完成。

## 为什么先接这条路径

- 本轮开发前的 v0.2.0 按整资产检查/导出，缺少稳定回合索引、图像预览、片段选择和冻结训练输入。
- 用户已明确需要真机/仿真组合、手动切段、来源采样和关键节点确认；它们依赖同一组回合/选择/产物基础。
- 先把这条路径真实做通，采集保存事件和外部下载以后可以共同接入回合库，避免分别重做处理页面。

三位审查者均建议保留四个全局工作区，以“当前任务”作为数据准备操作主区，将总体管线收为次级上下文。用户无需先理解内部数据库对象。

## 用户路径与交互决定

1. **选回合与预览**：回合表、筛选、来源和任务结果/结构质量；点行只预览，明确选择才进入本轮清单。右侧显示真实图像、帧位置、state/action 和问题。
2. **手动切段**：使用帧索引和 `[start,end)` 区间，提供设为起点/终点与键盘输入，保留源回合。缺少逐帧时间戳时标明估算依据；片段用途与源任务分开。
3. **组合与划分**：看到已选清单、来源分布和数量，设置自然分布或来源采样比例，预览按原始回合分组的训练/验证/测试划分。
4. **确认并准备**：集中核对清单和配置。确认后冻结来源指纹和选择，修改时另存草稿；实际构建提供日志、错误、重试与下载。

筛选不会清空已有选择；轮询不重置表单、帧位置和草稿。重叠区间、空选择、无效权重、组数不足和输入变化必须在对应位置解释。构建取消/失败后保留已确认的输入。

## 数据与接口决定

- 继续使用当前 Python 标准库、SQLite 记录和受管 worker；本轮不新增前端构建工具或 GPU 运行依赖。
- 回合由资产及相对 `data.json` 路径稳定定位，保存标注；原始媒体与 JSON 不被用户选数操作覆盖。
- 片段引用、划分、标注快照、源指纹形成训练数据清单。相同母回合与重复导入的相同源内容不跨划分。
- 确认清单与构建输入独立持久化；旧产物不随之后的标签或草稿编辑变化。
- 准备包包含实际选中数据、所需媒体、清单、配方、划分与契约；实际项目读取器验证样本和媒体，并验证来源采样规则生效。
- 产物明确 `is_lerobot_dataset=false`、`official_reader_verified=false`。官方适配器在独立环境中锁定版本，未来真正运行其读取器后再改变相应验收结论。

## 为什么本轮不直接在本机运行官方转换器

已核查的固定版本转换器和训练环境具有相机/FPS/字段约定及较重依赖。官方脚本的默认 writer 并发也不适合直接照搬到用户本机。接入时需要隔离环境、限定并发并核对动作/相机定义；不能因命令计划已生成就宣称转换成功。

## 真实设备和后续来源怎样接入

后续采集适配器提供任务、来源、本体/传感器配置、回合 ID、保存完成和文件清单。保存已确认且文件完整可访问后登记，后台排队质检；重复事件须幂等。真机、仿真和下载侧复用这套交接规则。

实时控制、XR 会话、录制状态核对、场景复位、DDS 目标隔离属于各适配器联调范围；软件界面按实际连接结果显示。当前尚未获得工作站连接信息，不把用户表示可提供硬件当成已通过环境或实机验收。

## 本轮验证

使用独立工作区与明确标注的轻量合成测试，另导入官方历史原始样例检查真实图像与未知字段呈现。检验切段帧对齐、源文件不变、分组隔离、确认冻结、采样、构建/读取、取消/恢复、路径和 wheel 安装，并通过浏览器实际走主路径及错误恢复。

自动化检查、浏览器使用验证、目标系统 GUI 点选和真实机器人/GPU 联调分别记录。本轮已通过的自动化、浏览器与安装包检查见[使用与验收说明](11_回合级数据准备与用户验收.md)；目标系统 GUI、硬件与官方训练器结论保持待验收。
