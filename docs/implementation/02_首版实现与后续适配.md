# 首版实现与后续适配

日期：2026-10-26；版本：v0.1.0。本文描述实际代码与下一阶段边界。长期需求仍见 `../product/`，没有在本版接入的能力不视为完成。

## 本版的用户闭环

单人打开工作台 → 设置任务、目标本体和策略 → 导入本机目录或主动创建合成样例 → 填写来源、授权、源本体与标签 → 查看资产 → 结构检查 → 查看问题 → 导出项目 JSONL → 查看日志和下载产物。

每阶段有独立按钮，也可选择“检查并导出”。失败会停止下游；未知授权与本体显示为缺项，结构检查通过仍不产生“可以训练/部署”的结论。首次启动没有演示数据、虚假成功率或假设备连接。

| 已实现 | 实现位置与边界 |
| --- | --- |
| 本机浏览器界面 | `robot_pipeline/workbench/static/`，纯 HTML/CSS/JS，无 CDN、Node 构建或联网字体 |
| 项目配置 | 保存任务、目标本体、策略；改变策略不会凭空改变采集到的信号 |
| 数据入库 | 本机绝对目录、来源类型、名称、任务、标签、许可、源本体；复制原始文件，生成 SHA256 清单 |
| 资产检索 | 按名称、任务、标签搜索；详情显示来源、格式候选和质量结果 |
| 结构检查 | 支持 Unitree 风格双臂双手 28 维 `qpos`；保留历史 `left_hand/right_hand` 别名适配；不等于全 43 DoF |
| 作业管理 | 单 worker、参数数组、日志、状态、输入配置快照、取消、超时、中断标记、工作区互斥 |
| 自有导出 | JSONL 数值与图像引用，加契约与来源；明确 `is_lerobot_dataset=false`、`training_ready=false` |
| 可搬迁工作区 | 内部保存相对 POSIX 路径；跨系统读取前重新校验；完整工作区需一起复制 |

导入上限 128 MiB / 10000 个文件，单个 JSON 上限 20 MiB。大规模数据、断点下载、远程对象存储、目录上传、资产编辑与删除尚未实现。当前质量检查不解码图像，只检查文件存在和路径；图像损坏、标定、真实采样同步、任务成功均需后续规则与人工验证。

## 代码与数据的组织

```text
浏览器 → loopback HTTP API → SQLite 资产/项目/作业目录
                                 ↓
                       受管理快照 + 哈希清单
                                 ↓
                  单 worker 子进程：check / export
                                 ↓
                 quality.json / records.jsonl / contract.json
```

- `http.py`：仅回环监听、Host/Origin/token 检查、受限制的静态与产物路由。
- `service.py`：资产导入、界面状态、作业提交、取消和进程回收；只允许运行登记好的阶段。
- `store.py`：SQLite 元数据持久化，启动时把残留作业标记为中断。
- `paths.py`、`locking.py`：便携路径校验、UTF-8、哈希、单工作区实例锁。
- `worker.py`：从作业输入快照读取本次配置，先验证全部文件集合和哈希，再检查与导出。
- `data.py`：当前已支持格式的读取、检查、展平与自有导出。

作业输出在 `jobs/<id>/`，原始副本在 `assets/<id>/raw/`。名称和中文标签不会直接变成路径。源目录保持原样；导入不是持续同步，后续修改来源时需重新导入。检查后若修改受管理副本或加入新回合，原快照不能继续导出。

源数据的任务文字与项目的目标任务是不同信息。项目改成“搬箱”不会把已有“烤面包”数据自动变为搬箱示范，源本体也不会因目标设置改变而被重写。

## 输出格式的实际含义

`records.jsonl` 每行一条记录，例如：

```json
{"episode_index":0,"frame_index":0,"observation.state":[0.0],"action":[0.01],"images":{"color_0":"image.png"},"task":"SYNTHETIC 工作台流程测试","timestamp":0.0,"synthetic":true}
```

上例仅把数组缩短展示，当前适配器实际导出各 28 个数值。`state` 是记录到的状态，`action` 是按当前 Unitree 原始 schema 解读的关节目标；该语义属于适配器假设，尚未与真机 SDK 报文逐项验收。契约保留 `action_semantics_verified=false`。

`contract.json` 记录字段维数、部位次序、输入资产与清单哈希、来源及合成标记、时间和图像基准。图像不嵌入 JSONL，路径相对于**该资产的 raw 根目录**。单独下载 JSONL 不包含完整图像训练集；搬迁/备份须保留整个工作区。这是可检查的中间契约，不是对所有策略通用的训练输入。

合成样例只有 12 条格式测试记录与小图，用于验证界面、进程、质检和导出；它不满足宇树官方转换器的四相机、图像尺寸与真实示范要求，不能拿它证明官方转换或训练已打通。

## 平台与模型的适配边界

当前界面中的策略设置是实验意图，不会启动模型或生成训练成功指标。后续按实际要用的少量配方实现，避免提前承诺所有组合。

| 目标 | 数据与转换要增加什么 | 训练与部署还要增加什么 |
| --- | --- | --- |
| 同一 G1 + ACT / Diffusion | 验证关节与相机、时序、LeRobot 版本/字段；已兼容的数据导出可复用 | 各自输入特征、时间窗口、chunk/horizon、归一化、划分和训练参数 |
| openpi | 已支持来源的 repack、机器人变换、统计与模型变换；可在读取时完成部分处理 | 具体配置、检查点、动作空间及机器人控制契约 |
| OpenVLA 原始路径 | 默认 RLDS/自定义数据接入；不能把 28 维任意裁成常见 7 维配方 | 动作维数、统计、tokenization、推理与控制逐项验证 |
| 在线 PPO | 示范不替代交互环境、奖励、reset 和终止条件 | 仿真场景、rollout、控制器与在线评价 |
| 新本体/手型/传感器 | 新本体档案、读取器、关节顺序/单位/动作定义、相机和标定；必要时动作迁移 | 本体仿真、控制与现场验收；仅同维数不代表兼容 |

官方固定转换器没有 `policy` 参数。`robot_type` 选择已有本体配置，不表示把任意来源迁移成目标机器人。哪些信号在采集时未保存，后处理通常不能补出真实值。详细源码证据见[报告的逐策略转换说明](../report/12_采集转换训练配置与策略适配.md)。

## 后续接口设计，尚未实现

下列是拟定边界，当前没有自动发现插件或多机代理服务：

1. `DatasetAdapter`：探测来源 → 读取元数据 → 验证 schema/语义 → 产出标准视图。每个适配器声明支持版本、字段、能力和缺项。
2. `CaptureAdapter`：预检设备与服务 → 准备会话 → 开始/结束录制 → 确认原始数据保存完成 → 停止。输入设备、动作映射、控制、视频和录制分别接入；真机启用保留明确控制权。
3. `ConversionAdapter`：输入契约与目标训练配方比对 → 给出映射/缺项 → 执行经过验收的转换 → 重新验收输出。转换不是简单改文件后缀。
4. `TrainingExecutor`：固定环境、参数数组、输入快照、资源需求和输出契约；训练位置可为 Linux Host/GPU/NPU 机器。支持状态、日志、取消和断线恢复。
5. `EvaluationAdapter` / `DeploymentAdapter`：分别声明场景、控制器、动作接口、成功标准和产物；数据导出成功不应使部署按钮自动可用。

新本体适配主要落在采集、数据语义、仿真控制和部署四处；界面、资产库、作业生命周期和来源追溯继续复用。Windows 客户端调用 Linux 执行器时传输结构化作业和文件引用，不能把 `C:\...` 路径原样当成 Linux 训练路径。

## 下一阶段建议顺序

1. 真机到货后核实 G1 配置、手型、PC2、网络与相机通道，按现有备查逐服务验收只读状态和保存链路。
2. 先接通官方固定版本转换器，在隔离的新缓存目录执行一小批真实回合；验证输出 schema、实际帧数、动作与图像对应。
3. 先选一种已确定策略（ACT 或 Diffusion），接入单一训练后端和任务场景，记录明确数据划分与成功标准，再加第二种配方。
4. 添加 Linux 远程执行器与作业资源检查，再接仿真视频与失败分析。真机部署单独验收。
5. 在实际新增来源/本体时补对应适配器，继续扩充资产分类、授权和采购验收证据。
