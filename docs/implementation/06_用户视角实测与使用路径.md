# 当前能做什么：用户视角实测与使用路径

实测日期：2026-10-26；程序版本 v0.1.0；开始试用时仓库 commit 为 `7e2f0d4`。本轮通过 macOS 的应用内浏览器操作页面，使用独立工作区，保留了成功、失败作业和下载文件，没有往日常工作区加入样例。

## 当前实现到哪一步

真正可以完成的链路是：**本机目录 → 复制入库与登记 → 结构质检 → 本项目 JSONL 导出 → 查看日志与下载产物**。各阶段可以单独点击，也可以串联“检查 → 导出”。

| 环节 | 当前实际能力 | 使用边界 |
| --- | --- | --- |
| 任务与目标配置 | 保存任务、目标本体和 ACT/Diffusion/openpi/OpenVLA/PPO 策略选项 | 保存实验意图并显示适配说明，没有接入这些策略的训练器 |
| 数据来源接入 | 导入服务机器上的目录，选择自行采集/开源/采购/仿真类别 | 网站、硬盘或网盘数据需先落到本机；没有自动搜索、联网下载或采购交付接口 |
| 资产整理 | 填写名称、数据任务、标签、来源本体和许可；按文字/标签与来源筛选 | 尚无完善的资产编辑、删除、版本谱系或自动任务适用性判断 |
| 原始数据保存 | 复制成受管理副本，保存文件清单与 SHA256，原目录保持原样 | 首版上限128 MiB、10000文件、单个JSON20 MiB，不适合整库大数据导入 |
| 质量检查 | Unitree风格28维双臂双手记录，包含历史hand字段；检查有限数值、维数、连续索引、记录时间戳和图像路径存在性 | 未解码图像，未检查物理关节范围、硬件同步、标定、任务成功或完整43DoF |
| 导出 | 生成 `records.jsonl` 与 `contract.json`，保留状态、动作、图像引用、任务与来源说明 | 不是官方 LeRobot/RLDS；不包含图像副本；不能直接视为某策略训练输入 |
| 作业与串联 | 状态、输入快照、日志、产物、取消与中断恢复；失败停止下游 | 当前只允许一个活动作业；本轮通过界面验证成功与失败链路，取消另有原生自动测试证据 |
| 数据增强 | 尚未接入 | 报告中的增强示意图不表示程序已有增强功能 |
| 真机/仿真采集 | 尚未接入 | 没有一键启动 Vision Pro、Host、PC2 或厂商服务的实际功能 |
| 官方转换、训练、任务仿真与部署 | 尚未接入工作台 | 仓库旧 CLI 的 state-only BC、固定机身仿真属于独立历史实验，不属于工作台训练按钮的完成度 |

## 我实际怎样使用

1. 在新的空工作区打开界面，设置“箱子从桌A搬到桌B”、目标本体和ACT，保存。
2. 点击“生成合成教学样例”，看到12条记录；未检查时“导出JSONL”不可用。
3. 单独点击“运行质量检查”，完成后再点击“导出JSONL”。在运行记录中实际点击下载 `contract.json`，核对合成标记与 `is_lerobot_dataset=false`。
4. 点击左侧“＋”导入官方历史原始回放样本，填写来源与标签，手工确认其任务不是搬箱；来源本体与许可保持unknown。
5. 勾选“检查通过后自动导出”，实际处理167条记录、335个文件；在页面看到完成状态、质检报告、日志及JSONL/契约下载链接。
6. 实际下载这次的 `records.jsonl`，与源JSON的167条state/action逐项比较，数值全部保留，维数均为28，原始任务文字保留。
7. 输入不存在的目录，确认显示错误、表单输入保留；直接在该表单中改为有效目录后重试成功。
8. 导入另一个明确标记为合成测试的6条记录样本，把第0帧 `left_arm.qpos` 动作维数改错。运行串联后检查失败，界面定位到该帧，导出按钮保持禁用，仅提供质量报告。
9. 按“历史回放”与“开源数据”筛选，在3份资产中找到1份；刷新页面后，配置、资产、质量结果和运行历史仍存在。筛选条件和选中项未做刷新持久化。

本轮没有执行真机动作、模型训练或任务仿真，也没有把早期实验视频算成本轮工作台效果。浏览器试用不能外推为Windows原生GUI实测；既有三系统原生CI证据见[首版验收记录](04_首版验收记录.md)。

## 你怎样开始使用

**报告演示ZIP包含PPT和配套资料。运行程序需要下载仓库源码ZIP，或使用工作台安装包。**

### 最短体验路径

1. 下载 [main源码ZIP](https://github.com/fengjikui/robot-data-pipeline/archive/refs/heads/main.zip)，全部解压，进入包含 `README.md`、`scripts`、`robot_pipeline` 的项目根目录。
2. Windows PowerShell中使用Python3.11+执行：

   ```powershell
   py -3 scripts/start_workbench.py --workspace ".workspace/main" --port 8765
   ```

   macOS/Linux用 `python3` 替代 `py -3`。基础源码入口不需要先安装实验依赖。

3. 打开终端显示的 `http://127.0.0.1:8765`；若端口已被使用，选其他空闲端口，同时使用正确工作区。
4. 暂无数据时主动生成教学样例。已有数据时点击“导入本地目录”，输入**运行服务这台电脑上的绝对路径**，选择来源、填写数据真实任务、标签、本体和许可。
5. 选中资产运行检查，阅读错误与警告；通过后导出，或选择检查后自动导出。
6. 在“运行记录”中查看日志、报告与下载。JSONL中的图像引用依赖该资产raw目录，正式搬迁应保留整个工作区。

独立环境、安装包、后台进程、日志、端口与停止步骤见[Windows Agent部署与启动指南](05_Windows_Agent部署与启动指南.md)。

### 当前使用时要注意的地方

- 项目任务是“你准备做什么”，数据任务是“这份数据实际做了什么”。当前导入表单会默认填入项目任务；导入外部数据时务必按真实内容修正，不能把烤面包/历史回放数据直接标成搬箱。
- 结构检查通过之后，仍应检查任务、本体、动作定义、相机与训练配方的适用性。当前系统没有自动完成这层判断。
- 授权、本体和时间信息未知时不要人为改成“已确认”。即使可以导出中间契约，仍不表示可训练或可部署。

## 本次试用发现的问题

以下问题保留为后续修复项。本轮完成用户试用与记录，程序代码保持不变。

| 优先级 | 问题 | 影响与建议 |
| --- | --- | --- |
| P1 | 源数据任务默认复制目标任务 | 可能误标外部数据；应改为空或读取源元数据，并保留人工确认 |
| P2 | 不存在目录直接显示Errno与路径 | 信息可用于排障，但用户提示应更直接地说明“目录不存在/请确认服务机器路径” |
| P2 | 切换资产/作业时，旧作业详情会短暂保留到异步响应返回 | 可能让人误认报告属于当前资产；应立即显示加载状态并隐藏旧下载链接 |
| P2 | 部分输入框maxlength与服务端字段上限不同 | 此项从源码核查发现，未在本轮浏览器里用超长文本复现；应统一前后端约束 |

此外，目前没有回合图像/动作轨迹预览、外部数据自动下载、通用格式适配、数据增强或训练后的效果展示。下一步最值得接通的是官方固定版本转换器与一种训练读取器，使数据从“可检查的中间导出”推进到“经过验证的可训练输入”。
