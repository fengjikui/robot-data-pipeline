# 真机采集接入现状与实施顺序

日期：2026-10-26。适用：工作台 v0.1.2。

## 目前做到了哪里

**真机采集已经调研、设计和编写手工操作材料，但尚未实现工作台对遥操作服务的启动、状态读取和录制控制。** 当前“自行采集”只是导入已保存数据时的来源标签，不是开始遥操作的入口。

| 环节 | 已有材料或软件 | 尚缺的实现 |
| --- | --- | --- |
| 设备与软件分工 | 报告设备图、Host/PC2/Vision Pro 分工、官方源码依据 | 实际设备档案与现场配置 |
| 启动流程 | 官方命令及启动顺序备查，服务编排设计 | 连接预检、服务状态、启动与清理接口 |
| 遥操作与录制 | 官方工具的 IPC、状态与 EpisodeWriter 行为调研 | Host 采集桥接、录制状态机、保存完成确认 |
| 数据入库 | 本地目录导入、原始快照与 SHA 清单 | 保存完成后自动登记回合与来源 |
| 后续处理 | 结构质检、自有 JSONL 导出、日志、取消 | 官方训练容器转换与模型/仿真/部署后端 |

前期实现只覆盖了数据落盘后的处理，范围比最初要求窄，不能称为完整的采集到训练管线。也不能把启动了上游进程、返回了 IPC ACK，或出现了目录当成录制完成。

## 下一步优先补齐的采集流程

用户依次看到：**配置设备 → 连接预检 → 准备服务 → 连接头显 → 确认跟随 → 开始/停止录制 → 等待保存 → 登记资产**。各阶段可独立执行；具备可靠状态之后再开放自动串联。

1. **设备档案与只读预检。** 保存 Host、PC2、相机、网络接口、手型和输出位置；检查网络、依赖、版本与已有服务。预检不能运行会发布机器人指令的遥操作主程序。
2. **Host 采集桥接。** 包装固定版本的官方工具，提供结构化状态、日志和受限操作。工作台可在 Windows/macOS/Linux 运行，实际厂商工具按其支持环境运行，不能据此承诺所有设备软件都支持三平台。
3. **服务编排。** 按依赖准备 PC2 图像服务、Host 图像/遥操作连接；复用已运行的厂家基础服务。只记录和清理本次启动的进程。Vision Pro 的 Safari/XR 连接步骤仍需要操作者完成。
4. **录制状态机。** 区分待连接、就绪、跟随、录制、保存中、完成和失败。上游 `CMD_RECORD_TOGGLE` 是切换命令，不能盲目重试；需要桥接层确认当前状态，提供面向用户的开始/停止语义。
5. **保存完成与入库。** 桥接层在 EpisodeWriter 完成落盘后给出回合清单与输出位置；通过文件完整性检查后登记资产，再进入已有质检流程。未完成回合不得自动导入。

## 没有真机也能先做什么

设备配置、受限接口、状态机、进程编排、断连/超时处理、模拟采集适配器，以及“保存完成 → 入库 → 质检”可以先开发与测试。模拟适配器必须明确标为模拟，不生成真机验收结论。

真机到场后再验收网络拓扑、相机实际数据、状态/目标动作的对应关系、录制时序、停止后的落盘完整性及现场控制行为。硬件到货不是前述软件开发的前提。
