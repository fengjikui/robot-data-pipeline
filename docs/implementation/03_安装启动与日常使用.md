# 安装、启动与日常使用

版本 v0.1.0；需要 Python 3.11+。本版单用户运行在本机，只监听 `127.0.0.1`。基础工作台不需要 GPU、Node、MuJoCo、Torch 或厂商 SDK。

由 Agent 在 Windows 上安装和启动时，优先使用[Windows Agent 部署与启动指南](05_Windows_Agent部署与启动指南.md)，按其中的进程、日志和验收步骤交接。

## 源码启动

下载/克隆本仓库后，在项目目录执行。不要用旧项目目录覆盖当前项目。

macOS / Linux：

```bash
python3 --version
python3 scripts/start_workbench.py --workspace ".workspace/main" --port 8765
```

Windows PowerShell：

```powershell
py -3 --version
py -3 scripts/start_workbench.py --workspace ".workspace/main" --port 8765
```

`py -3` 需指向 Python 3.11+。若机器没有 `py`，可以用已安装 Python 的完整路径；路径带空格时，PowerShell 使用调用运算符：

```powershell
& "C:\Path With Spaces\Python\python.exe" scripts/start_workbench.py --workspace "D:\robot data\项目" --port 8765
```

上面的 Python 路径仅为语法示意，需替换为实际路径。打开终端显示的 `http://127.0.0.1:8765`。关闭终端/按 Ctrl+C 退出；不要用“结束所有 Python”处理端口问题。

## 独立安装

建议给本工作台创建独立轻量虚拟环境，以后训练环境另建。

macOS / Linux：

```bash
python3 -m venv .venv-workbench
.venv-workbench/bin/python -m pip install .
.venv-workbench/bin/python -m robot_pipeline.workbench --workspace ".workspace/main"
```

Windows PowerShell：

```powershell
py -3 -m venv .venv-workbench
.venv-workbench\Scripts\python.exe -m pip install .
.venv-workbench\Scripts\python.exe -m robot_pipeline.workbench --workspace ".workspace/main"
```

不需要激活 `Activate.ps1`，也不需要调整执行策略。wheel 可以在一台联网机器构建后拷贝到目标机器，用 `python -m pip install --no-index 路径.whl` 安装；目标仍需 Python 3.11+。

## 第一次操作

1. 打开空工作台，设置任务、目标本体和策略，保存配置。
2. 若只验证程序，点击“载入合成样例”。它是格式测试记录，不是真机数据，不应进入正式训练。
3. v0.1.1起可点击“选择文件夹…”浏览目录，再点击“使用此目录”回填；也可填写该电脑上的绝对路径。Windows 示例 `D:\robot data\episode_0001`；macOS/Linux 示例 `/home/user/robot data/episode_0001`。从网页复制的路径不要额外加引号。详见[路径选择与三平台说明](07_路径选择与三平台说明.md)。
4. 确认名称、来源、任务、标签、授权与来源本体。复制完成后才出现成功资产；原目录不被修改。
5. 选中资产运行检查，阅读错误、警告和检查范围。修正来源文件后重新导入，不能修改受管理快照后继续沿用原结果。
6. 通过后导出，或选择“检查并导出”。打开运行记录查看真实日志和产物下载。

未接入的训练、仿真、采集与部署入口显示原因。选择 ACT 等策略不会使自有 JSONL 自动成为相应框架的训练数据，详见[首版适配说明](02_首版实现与后续适配.md)。

## 工作区、搬迁与备份

工作区包含 SQLite 数据库、原始副本、哈希清单与作业文件。退出工作台后复制**整个工作区**，再用新电脑上的程序指定新位置启动。内部数据引用不带旧盘符；源目录不需要跟着搬迁，作业处理使用受管理副本。

- 同一个工作区只允许一个工作台实例；第二次启动会提示已被使用。
- 工作区不要放到源码需要导入的目录里面，避免递归复制。
- Windows 优先选择较短位置，例如 `D:\robot-data`；不要依赖系统已开启长路径策略。
- JSONL 下载不包含图像，图像路径相对于原始资产目录；正式交付训练集还需要目标格式打包适配器。
- 本版没有资产删除、迁移数据库版本或多用户并发功能；备份后再升级程序。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 提示需要 Python 3.11+ | 检查命令实际指向的解释器，不要使用旧系统 Python |
| 端口被占用 | 用 `--port 8766` 启动新实例；不要终止不属于本项目的进程 |
| 目录找不到/不能导入 | 使用服务机器上的绝对目录；支持的来源不含符号链接、junction、跨平台非法名字和大小写冲突 |
| 导入超限 | 首版限制 128 MiB / 10000 文件、单 JSON 20 MiB；先准备小批完整回合验证 |
| 质检通过但仍不能训练 | 当前是结构检查；授权、任务、本体、时间、相机、策略读取器仍需验收 |
| 修改快照后导出失败 | 属于预期保护；修改来源并重新导入，不要改清单来跳过检查 |
| 浏览器提示令牌失效 | 服务可能已重启，刷新页面重取本次会话，再重试阶段 |
| 重启后作业为中断 | 查看日志，从该阶段重新运行；不会假装继续或覆盖已成功产物 |

跨平台限制和测试证据的口径见[架构与验收设计](01_跨平台架构与验收设计.md)。报告播放包与工作台是两个独立交付物，Windows 工作台 CI 不代表 PowerPoint/WPS 播放已经测试。
