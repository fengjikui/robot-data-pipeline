# 回合级数据准备：使用与验收

日期：2026-10-31。本文对应本轮数据准备迭代，具体版本号以工作台显示为准。

本轮把“导入一整个目录后直接导出”推进到“查看回合 → 标记与筛选 → 手动切段 → 组合与划分 → 确认 → 构建可追溯产物”。真机和 GPU 联调不在本轮本机验收中；独立测试结果见文末。

## 1. 当前能力与边界

| 对象 | 本轮能力 | 需要区分的结论 |
| --- | --- | --- |
| 原始数据 | 复用本地目录导入和原件快照，枚举已支持的 Unitree 风格回合 | 来源标签不是设备实测证明，格式识别不等于动作语义已验收 |
| 回合预览 | 查看实际图像、帧位置、state/action；分别显示技术质量和任务结果 | 单帧查看不是模型闭环运行；数据完整不代表搬箱成功 |
| 任务结果 | 标记成功、失败、中断或待标，保存备注，支持之后修改 | 人工标记不改写原始录制文件；失败回合仍保留 |
| 手动切段 | 整回合选择或保存多个半开帧区间，给片段注明用途 | 选中失败回合的一段不会自动把父回合变成成功示范 |
| 数据集草稿 | 跨已支持来源组合、查看问题、设置划分与采样比例 | 组合只保留选数和配置关系；不增加原创示范数量 |
| 确认与构建 | 冻结输入快照、真实构建记录和媒体、执行项目读取器检查，打包下载 | 产物是项目中间契约，不是官方 LeRobot 格式 |
| 采集/训练/仿真后端 | 保留后续接入位置 | 本轮不声称已经启动真机采集、训练策略或完成闭环仿真 |

输入仍受现有本地导入限制约束：每个目录最多 128 MiB / 10,000 个文件，单个 JSON 不超过 20 MiB。大规模数据获取、官方转换与具体训练器需在后续迭代中接入，不因增加数据准备界面就自动具备这些能力。

## 2. 启动

在仓库根目录执行：

```bash
# macOS / Linux
python3 scripts/start_workbench.py --workspace ".workspace/main" --port 8765
```

```powershell
# Windows PowerShell
py -3 scripts/start_workbench.py --workspace ".workspace/main" --port 8765
```

打开终端显示的本机地址。新工作区没有默认数据。服务和数据保存在指定的工作区，关闭浏览器不会删除数据；若停止工作台服务，运行中作业按实际状态中断并记录。

## 3. 从一份数据完成准备

### 3.1 导入并查看回合

在数据集库选择本机目录，填写真实来源、来源任务、本体、使用条件和标签。外部数据中的实际任务不应直接填成自己的目标任务。选择目录使用服务所在电脑的原生选择器。

进入“当前任务”页的“准备本轮训练数据”，依次经过“选回合与预览 / 组合与划分 / 确认并构建”。按任务文字、来源、质量、任务结果等条件查找回合；点击回合名称只查看预览，勾选复选框才选择整回合。不支持的格式应按实际情况显示待适配，不能产生虚构预览。

对于仓库历史官方样例：

`examples/raw/official_rerun_testdata/episode_0006/`

它包含 167 帧，任务是历史红杯示例，非搬箱示范。逐帧数据没有 `timestamp`，仅有图像标称 30 FPS，因此显示的估算时间不等于实测采样时间或同步证明。其关节名称元信息也不完整，不能据此声称全身动作映射已通过验收。来源说明见该样例父目录的 `README.md`。

### 3.2 标记任务结果

“质量通过”描述当前检查范围；“任务成功/失败”描述这次尝试的结果，两者分开处理。例如图像和动作记录完整但杯子掉落，仍可以是“结构通过、任务失败”。

操作者可当场标记或事后补标，并写备注。标记更新使用版本检查，较旧页面提交的修改不会悄悄覆盖较新结果。需要时刷新后重新核对。

### 3.3 整回合选择与手动切段

保留整回合，或在“保留一个时间片段”中输入要保留的起始帧和结束帧，再点“加入此片段”。区间采用 **`[起始帧, 结束帧)`**：起始帧包含，结束帧不包含。已经选中整回合时，页面明确显示“用此片段替换整回合”，可撤销；这样不会无意间把整回合和其中同一片段一起加入。

例如 `[20,60)` 表示原始第 20 至 59 帧，共 40 帧。每个片段独立保留母回合和原始帧索引；多个不连续片段不会被伪装成一次连续动作。可为片段注明任务用途，但不要将局部成功标成整个搬箱过程成功。

切段不覆盖原始文件。没有可靠逐帧时间时，以帧索引为准；有时间戳时原值保留，缺失时保持未知。边界非法、空片段、超出回合范围时应得到明确提示。

### 3.4 组合、划分与来源采样

将真机、仿真或其他已支持来源的回合/片段加入同一份草稿，进入“组合与划分”，设置后点“保存并预览划分”，查看选定内容和问题。

- 默认按实际训练记录的分布采样。
- 自定义来源权重改变训练时的抽样频率，不复制或增加原始示范。零权重的来源仍可保存在准备产物中，只是不在该训练抽样配置中被选到。
- 来源权重只作用于训练子集；验证/测试按固定清单保留。
- 划分以母回合/重复内容分组，不能把同一个回合的切段或重复导入副本分散到训练和验证两边。
- 默认划分为训练 80%、验证 20%、测试 0%；这里按分组划分，最终记录数量比例可能不同。数据太少时先增加独立回合，或明确选择“全部用于训练”；仅训练不能充当留出评估。

当前项目读取器的记录采样检查不等于某个策略的时间窗口读取验收。接入 ACT、Diffusion 等实际训练后端时，还需确认观察/动作语义、相机、归一化和窗口长度。

### 3.5 确认、构建与读取检查

对照问题清单核对训练数据选择。满足条件后点“确认并构建准备包”；确认后不直接改写其内容，下一轮可“基于此版本新建”，保留旧选择和作业关系。未准备好时先保存草稿，之后载入继续。

构建产生实际文件并保留作业输入快照、日志与结果。若原始快照发生变化，构建应阻断并提示，不悄悄使用变更后的数据。检查或确认通过也不会自动把项目数据标为官方训练格式。

成功后下载 ZIP，解压到独立目录查看：

| 文件 | 作用 |
| --- | --- |
| `records.jsonl` | 选定的记录、实际状态与目标动作、任务、来源、原始索引、划分和媒体引用 |
| `images/` | 实际使用的图像字节，采用包内相对路径，不依赖原资产的绝对路径 |
| `manifest.json` | 准备产物和来源对应关系及校验信息 |
| `contract.json` | 项目数据契约和能力边界，包含非官方 LeRobot/未验证官方读取器的声明 |
| `splits.json` | 固定的数据划分 |
| `sampling.json` | 来源采样配置 |
| `reader_check.json` | 项目读取器真实读取记录/媒体和执行抽样检查的结果 |
| `reader.py` | 便携的标准库项目读取器，可从解压目录读取与采样 |

读取检查通过说明当前项目契约与实际媒体能被这个读取器使用，**不表示 LeRobot 读取器已通过，也不表示模型已经训练完成**。

若需要独立核对解压包，可直接运行其中的读取器；它默认以脚本所在目录作为数据根目录，不要求安装本项目：

```bash
# macOS / Linux；替换为实际解压路径
python3 "/path/to/unpacked/reader.py" --draws 128
```

```powershell
# Windows；替换为实际解压路径
py -3 "C:\data\unpacked\reader.py" --draws 128
```

输出包含读取记录数量和实际抽样来源分布。它读取包内真实图像字节，不进行完整像素解码或官方策略读取验收。

### 3.6 查看错误、取消和重试

运行记录显示阶段、输入版本、日志和产物。构建失败不会覆盖原件，也不会使确认过的选择消失。

执行中可请求停止本次作业；部分产物不标为成功。错误处理或取消后，可对同一份仍然有效的确认输入重新构建，产生新的作业记录。若输入选择或重要配置改变，应另存新草稿并重新确认。

## 4. 供开发 Agent 使用的轻量验收数据

测试样例由标准库生成，不需要 Pillow、GPU、机器人或互联网：

```bash
python3 tests/preparation_fixtures.py --output ".build/preparation-fixtures-new"
```

输出包含三个独立有效源组、一个缺图回合及一个完整重复源。所有原始 JSON 均含 `info.synthetic=true`；导入验收时还必须保留合成标记，不能将来源类别填写为“自行采集”就隐去它是合成数据的事实。

本轮已生成的本机 QA 目录为 `.build/preparation-fixtures-2026-10-31/`。这个目录不是正式用户数据，未默认加载到新工作区。真图片预览由主代理另行导入上述历史官方回合核对。

## 5. 独立验收记录

状态：独立 HTTP/API 验收已通过；浏览器完整使用路径、安装包及三平台结论分别记录，不能互相替代。

独立测试文件：`tests/test_preparation_api.py`。运行：

```bash
python3 -m unittest discover -s tests -p "test_preparation_api.py" -v
```

覆盖的验收对象包括：

1. 回合列表、来源筛选、真实 PNG 预览、任务标记、CSRF/跨站与非法图片路径拒绝。
2. 半开片段的帧数、state/action/时间/媒体对齐、原件不变及失败父回合标签保留。
3. 无逐帧时间戳时保持未知；重复内容不能跨训练/验证集合。
4. 草稿 revision 冲突、确认后的内容冻结、组不足与缺图阻断、非法切段及权重输入。
5. 真正解压读取 ZIP 内的记录和图像，并在项目读取器中验证来源权重实际作用，而非只检查配置被保存。
6. 未确认版本不能构建；取消、进程错误与源快照变更阻断，以及恢复后的真实重试。

### 5.1 独立自动化结果

2026-10-31 在本机 macOS、Apple Silicon、Python 3.14.3 上独立串行执行：**14 项全部通过，最后一次复验耗时 9.174 秒**。每项使用独立临时工作区，结束后清理；只运行标准库服务与小规模项目 worker。

测试真实下载并解压准备 ZIP，再在原工作区之外调用包读取器，检查选中记录与图像字节；另以独立解释器 `python -I` 执行包内 `reader.py`，确认它无需项目环境即可读取 11 条选中记录、实际抽样 16 条。半开区间的 state/action、时间和来源索引与原始输入逐条比对，并校验外部原目录及工作区内原始快照的文件哈希均未改写。自定义权重 `self_capture=1, simulation=0` 的实际抽样返回 128 条，均来自前者，而产物仍保留两种来源的数据。

另验证了普通目录导入不依赖隐藏参数也能保留 `info.synthetic=true`、相同来源重复导入不能跨集合、无逐帧时间戳保持未知，以及受控真实子进程取消/失败后的重新构建。

本轮独立测试发现的全新工作区构建目录创建、ZIP 目录层级和普通导入合成标记问题，已修复后重新通过以上验收。测试前资源检查显示系统可用内存比例 54%，无已记录的热或性能警告；没有具体温度读数。

后端 agent 另外报告：原有 53 项回归为 52 项通过、1 项因当前文件系统不能创建仅大小写不同文件名而跳过；新增 8 项领域边界测试通过。这两组为后端执行结果，独立最终复验对应上面的 14 项。
