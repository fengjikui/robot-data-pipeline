# v0.2.0 任务式工作台框架与演示

这版先验证“围绕同一个任务、同一份输入连续操作”的产品结构。无需服务器、GPU、机器人或新前端依赖。基础服务继续使用 Python 标准库和原生浏览器页面。

## 现在解决什么问题

原来从资产详情出发，用户需要自行记住当前任务和处理进度。现在先确定任务、本体与策略，再从自行采集或外部数据进入。选定的输入会保存到工作区，检查、派生导出和运行记录都关联这份输入。

四个工作区的分工：

| 工作区 | 用户能完成的动作 | 当前执行范围 |
| --- | --- | --- |
| 当前任务 | 设置目标组合、选择数据、查看七个阶段、运行或串联已接入步骤 | 结构质检、工作台 JSONL 导出可执行 |
| 数据集库 | 选择本机目录、登记来源/任务/本体/标签/交付编号、按条件查找、查看数据档案 | 原件快照、文件清单、哈希、检查结果真实保存 |
| 设备与采集 | 保存 Host、PC2、相机、手部和本机接收目录；将保存的目录交给导入 | 配置保存，不启动设备服务 |
| 运行记录 | 查看实际作业、输入与配置快照、日志、错误和下载产物；停止执行中的作业 | 独立目录、串行 worker、取消和中断恢复 |

任务页的“数据转换”当前只能导出项目中间契约 `records.jsonl` / `contract.json`。这不是官方 LeRobot 数据。数据增强、策略训练、仿真测试和真机部署仍需接入相应后端，页面明确标明状态。

## 启动与第一次使用

在仓库根目录执行；Windows 使用 Python 启动器，避免依赖 shell 激活脚本：

```bash
# macOS / Linux
python3 scripts/start_workbench.py --workspace ".workspace/main" --port 8765
```

```powershell
# Windows PowerShell
py -3 scripts/start_workbench.py --workspace ".workspace/main" --port 8765
```

打开终端显示的本机地址。新工作区没有任何预置数据。

1. 在“当前任务”顶部编辑任务、本体和拟采用策略；这里只保存目标组合。
2. 有数据时点“导入目录”，用系统原生选择器选目录并填写来源信息。外部数据的任务描述应填写数据实际包含的操作，不要复制目标任务作为兼容性结论。
3. 没有数据时，主动点击“生成合成教学样例”。它只有 12 帧，用于验证交互和文件流转。
4. 确认“本次处理的数据”，点“质量检查”。可单独运行，也可勾选通过后自动导出 JSONL。
5. 在阶段的最近运行或左侧“运行记录”打开作业，查看日志、输入快照并下载产物。
6. 切换到“设备与采集”保存配置。目录必须是运行服务这台电脑上的已有目录；远程 Host 的路径不由本机目录选择器处理。

不支持的格式也可以先登记，但当前检查器只支持 Unitree 原始 JSON 的 28 维双臂与双手结构。导入上限 128 MiB / 10,000 文件；单 JSON 20 MiB。大数据集下载、选取子集和流式管理是下一批工作。

## 用真实原始回合验证

仓库内的历史官方回合可以用来验证文件流转：

`examples/raw/official_rerun_testdata/episode_0006/`

通过系统选择器选择这个目录，名称建议填写“Unitree 官方原始回合（历史样例）”，数据任务填写“历史采集格式示例，非搬箱任务”。它有 167 条记录。原始来源与固定版本在 `examples/raw/official_rerun_testdata/README.md` 中。

这份数据能验证导入、检查和导出；不能据此证明搬箱任务、策略训练或闭环仿真成功。

## 后续接入顺序

1. **把首条 G1 路径接实**：给 Host / PC2 编写明确的服务适配器，接入图像与遥操作进程状态、回合开始/结束、保存完成事件；新增回合自动进入同一资产与质检流程。
2. **接官方转换器**：锁定版本和一套本体/相机/动作配置，用 LeRobot 实际读取产物验收，替代人工搬目录、改参数与查错误。
3. **做一条外部数据路径**：先支持一个明确来源的数据集目录检索、按任务/回合选择、可恢复下载和入库。匹配任务、本体、动作语义后再选择转换器。
4. **接训练与仿真**：只接一套经过验证的策略/环境组合，把输入版本、训练配置、模型与仿真回合连起来，再扩大策略范围。
5. **扩展数据仓库和本体**：根据实际数据量加入对象存储、索引、加载优化和更多适配器，避免首版承担所有格式和设备。

## 接口与运行约束

- `GET /api/state` 返回当前任务、采集配置、资产与作业状态。
- `POST /api/project` 可保存当前 `asset_id`；切换输入不改写旧作业的输入快照。
- `POST /api/capture/config` 只保存限定的文本字段和已有本机目录；不接受命令字段，不建立 SSH 连接。
- `GET /api/jobs/<id>` 返回作业、日志、结果及创建时的 `input.json` 快照。
- 所有写接口保留本机来源检查和操作令牌；页面把外部名称、来源与日志作为文本显示。
- 基础运行不依赖 Node、GPU、第三方 Python 包或 Windows PowerShell 执行策略。
- 现有三平台 CI 保留；本次本机浏览器使用测试在 macOS 上进行，不能替代 Windows / Linux 的原生 GUI 点选测试。
