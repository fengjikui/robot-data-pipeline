# 仿真演示与算力计划

## 今天的真实实验

选择宇树官方 `G1_Dex3_ToastedBread_Dataset` 的数值分片，revision 固定为 `02cb29161f5adb2981a072aa35b408d82a556d07`。它与当前推断的双臂双手配置较接近，已提供 LeRobot 数据，适合验证导入与学习。任务是烤面包操作，不是搬箱；没有把这份数据改名包装成搬箱示范。[S07]

本轮只下载一个约 73 MB 的数值 Parquet 分片，以及 G1 43 关节 MuJoCo 模型和必要网格。没有下载整套四路视频。使用前 16 个完整回合，共 21,001 帧；训练回合 0 至 9，验证回合 10 至 12，测试回合 13 至 15。训练实际使用 12,935 帧，验证 4,104 帧，测试 3,962 帧。

模型是小规模 state-only residual behavior cloning：输入当前 28 维实测关节位置，构造线性特征和 192 个固定随机 Fourier 特征，拟合 action 减 state 的残差。用验证集选择岭回归强度，再一次评估测试集。这是实际拟合出的模型，没有调用大模型 API，没有使用图像、语言或强化学习。

| 数据划分 | 模型 RMSE rad | 直接用当前 state 的 RMSE rad | 训练集均值基线 RMSE rad |
| --- | --- | --- | --- |
| 训练 | 0.03126 | 0.04305 | 0.27762 |
| 验证 | 0.03734 | 0.04009 | 0.26264 |
| 测试 | 0.06642 | 0.04745 | 0.38078 |

测试集上模型弱于 state 保持基线。这是一个有用的失败结果：损失能下降，且模型优于固定均值，但对未见回合的动作变化预测仍不够好。当前关节角缺少视觉、物体状态和任务阶段，还受到样本覆盖与分布差异影响；仅凭本实验不能确定哪项因素是主要原因。没有在看过测试结果后继续调参挑选漂亮指标。

指标衡量目标关节角预测误差，不等于实际执行误差，更不是任务成功率。训练 split 都来自同一个数据集的同一任务；测试集没有提供跨桌面、跨场景或跨机器人的泛化证明。完整参数、数据哈希和指标见 `artifacts/bc_run/metrics.json`。

## 两段视频各自证明什么

`g1_offline_predictions.mp4`：左边把测试回合实测 state 投影到 G1 模型，右边把模型基于该实测 state 预测的 action 投影到同一个模型。每一帧的输入仍来自记录数据。这是离线预测的运动学可视化，使用 `mj_forward`，没有逐步物理积分，也不是自主策略 rollout。

`g1_fixed_pelvis_closed_loop.mp4`：左边仍是记录状态回放；右边读取仿真的关节反馈、运行学习模型、做位置目标限幅，然后执行 MuJoCo `mj_step`。机身骨盆固定，腿部不学习，推理 30 Hz，物理积分 300 Hz。本次 360 步中，10,080 个动作目标分量有 5,674 个超出模型关节范围，被控制器截断，比例约 56.3%。这暴露了闭环分布漂移与输出约束问题，模型不能部署；有限的数值状态不等于行为合格。它说明模型可以进入一个短时闭环仿真链路；不含原数据的烤面包机、桌面交互或搬箱场景，因此不对任务成功做评价。

两个视频都采用公开的 G1 43 关节描述，数据只控制 28 维双臂与手；关节通过名字映射，没有按 XML 的第几个关节盲目拷贝。手部符号、零点、硬件固件差异和接触模型尚未经过真机标定。固定骨盆会移除平衡难度，所以不能把“机器人在画面里没有倒下”解释为学会站立。

## 官方 G1 任务仿真的下一步

使用 `unitree_sim_isaaclab` commit `e30c25b1dffdf92ada1d6c8c1fe9a47bdde0fecc`。先按其 README 安装匹配的 Isaac Sim/Isaac Lab 与资产，再启动与手型对应的任务。固定基座 Dex3 圆柱抓放可用以下官方命令模板，当前未在本机执行：[S08]

```bash
python sim_main.py --device cpu --enable_cameras \
  --task Isaac-PickPlace-Cylinder-G129-Dex3-Joint \
  --enable_dex3_dds --robot_type g129
```

这里 `--device cpu` 不意味着 Isaac 的图形系统不需要 NVIDIA GPU。图像服务、渲染、驱动、容器 GPU 图形能力和资产可达性都要检查；只看到 `nvidia-smi` 或安装了 PyTorch CUDA 不能证明 Isaac 能启动。[S13]

用 Vision Pro 遥操作仿真时，在 Host 的遥操作程序加入 `--sim --record`，相机服务 IP 改成仿真运行机地址。Host、仿真、头显间需要可达网络；不能把局域网 DDS 指令随意穿过公网，建议建立受控网络并与真实机器人隔离。

下一步最可靠的实验是：在同一个圆柱抓放场景采集仿真示范，转换成相同动作空间，训练 ACT 或 Diffusion，再在该场景用模型闭环执行并统计成功。官方提供 `Wholebody` 移动任务，但没有证明桌 A 到桌 B 的自定义抱箱任务已开箱即用。需要先增加两张桌子、合适箱体、抓持接触、路线、初始分布、成功判定和失败条件。

## 仿真数据生成命令的真实含义

官方示例支持：

```bash
python sim_main.py --device cpu --enable_cameras \
  --task Isaac-Stack-RgyBlock-G129-Dex1-Joint \
  --enable_dex1_dds --robot_type g129 \
  --replay --file_path /data/raw_sim \
  --generate_data --generate_data_dir /data/augmented_sim
```

这是 Dex1 任务的官方示例，不能把它直接当成 Dex3 搬箱命令。加入 modify_light 或 modify_camera 前，需在对应函数中配置增强规则，并抽样检查新图像、动作时间和任务有效性。真实数据若缺乏可重建的场景状态，通常不能直接导入仿真并保持相同接触。

## 开源数据优先候选

| 数据 | 已核实格式 | 当前适用性与限制 |
| --- | --- | --- |
| G1_Dex3_ToastedBread_Dataset | 本次实际 meta v3.0，28 维 state/action，30 Hz，4 路相机 | 配置接近 Dex3，用于本轮管线实验；任务不是搬箱 |
| G1_WBT_Brainco_Plastic_Box_Parts | v3，多组 state/action，含 lower_body 和 base_command | 全身移动操作候选，但 BrainCo 手与 Dex3 不同；名称含 Box 不能证明任务就是搬箱 |
| G1_WBT_Inspire_Pick_Up_Multiple_Cushions | v3，多组状态与动作，30 Hz | 可研究抱持与全身数据结构，但物体和手型都不同 |

三个数据仓库的固定 revision、info 与数据卡已保存至 `evidence/datasets/`，所查元数据声明 Apache-2.0。除第一个数值分片之外，本轮没有下载和训练完整 WBT 数据。迁移前要检查真实任务视频、授权范围、手型、相机、坐标系、动作频率和字段；不能承诺任何厂商的 LeRobot 文件都能直接迁移。

WBT 的 `lower_body` 已含腿和腰，同时又有独立 left_leg、right_leg、waist 字段，它们不是互不重叠的新增自由度。其手腕命名顺序与旧 Dex3 扁平向量也不同。四元数示例用 qx qy qz qw，而 MuJoCo 的自由基座状态有自己的排列约定；必须按 schema 显式转换。这是第二条主线要做的适配工作，不应在第一轮里隐式完成。

## 算力选择与租赁条件

今天这个数值训练无需租服务器。后续若同时做视觉策略和官方 Isaac 仿真，可先考虑一台 x86-64 Linux、经相应 Isaac 版本兼容检查的 RTX 机器，单卡启动、单个环境、一个任务。24 GB 级显存和 64 GB 级 RAM 可作为小实验的候选配置建议，不构成对任意任务、模型和 Isaac 版本都能运行的保证；运行前核查具体版本要求、驱动、渲染能力、数据盘和资产下载量。[S13]

只有 CUDA 计算能力的卡不一定满足渲染要求。云机器优先做兼容性检查、场景启动、图像读取和 100-step 训练检查；这些通过后再按实际显存和速度扩大。先不要购买长时算力或启动大规模数据下载。用户在 AutoDL 提供实例访问方式及单次预算后，才安排会产生费用的训练。

历史记录提及可用的昇腾 A3 节点，但本轮没有核实它的具体配置、软件栈或占用。它可以作为后续训练适配的候选；不能把它视作 Isaac 的 NVIDIA RTX 渲染环境，也不能默认 LeRobot CUDA 命令可在 NPU 上直接运行。

本机遵守单个实验、数值库单线程、视频编码单线程。训练和渲染前后保存 load、memory_pressure 与 pmset 热状态记录；没有可用温度传感器读数，因此不提供具体温度。出现内存或热压力时仅降低或停止本任务创建的进程。
