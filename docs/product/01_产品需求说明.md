## 1 执行摘要 Executive Summary

### 问题

采集、数据处理、训练、仿真和部署由不同设备、服务、脚本和目录承担。外部数据又分散在网站与交付目录，重复发现、归档和核对用途需要人工工作。操作者不容易知道阶段是否真正完成、哪些数据适合当前训练组合，或更换设备/来源会影响哪些步骤。

### 方案

提供一个可配置的图形工作台，用设备档案、阶段按钮和运行记录组织这些工具。首先接通单人单台宇树 G1 的完整链路，再通过适配器接入其他来源和机器人。框架与厂商 SDK、记录器、训练框架和仿真器协同，不在网页后端重新实现机器人实时控制。

### 需求依据

用户明确要求：跨设备启动采集；图形界面；阶段按钮与可选串联；支持自行采集和外来数据；先接通 G1，同时预留换厂商/本体的边界。这些是已确认需求。页面编排和后端技术方案属于本轮设计建议；尚未做多人用户研究、原型测试或工程可行性实机验收。

新增确认：外部数据需要便捷导入、分类归档、检索和重复使用；先支持实际采用的少量本体与训练配方，新增对象通过接口扩展。任务/方法/本体作为需求线索，字段与判断规则由调研和实际样本迭代完善，不当作用户已给定的标准。

### 成功标准

1. 完成一次初始化后，操作者从工作台重复完成 3 次采集会话，无需另开终端手工启动已接入服务；界面提示必须在头显或现场完成的步骤。
2. 每次会话至少保存并查看 10 个回合；界面可区分正在录制、正在保存、已保存、异常中断，不把进程存在当作数据完成。
3. 对一个固定的 G1 任务配置，从有效回合得到可被指定训练后端加载的样本，实际完成一项训练和一次匹配场景的闭环仿真评估，保留配置、日志、指标、模型和视频。
4. 人为注入相机中断、服务失联、磁盘不足或转换失败时，作业显示具体失败阶段、设备和恢复入口；未完成输出不进入训练候选集合。
5. 外部数据可登记、导入、筛选并保存训练视图，再次使用可复用元数据和适配产物；在第二个已接入来源/配置上验证通用页面与作业复用，未接入组合不自动放行训练。

第 3 条不要求第一次训练即达到搬箱成功率，但必须实际做闭环评价；不能用离线损失或运动学回放替代。任务成功阈值由具体任务配置规定。

## 2 用户体验与功能 User Experience and Functionality

### 首期用户与使用方式

一个有基本机器人经验的操作者，操作一台机器人或其仿真替身，可能配一台 Host、一台机载计算单元和一台训练机。默认使用本地浏览器工作台，由 Host 或局域网服务提供；这是部署建议，尚未锁定前端框架或桌面封装。

用户每次先选择项目、目标设备和数据来源。机器人及相机配置保存在档案中，不要求每天重填。首次安装、网络配置与证书信任采用向导和检查结果；重复使用调用已验证模板。首期不把“机器人物理开机、穿戴头显、进入 XR 会话”承诺为纯软件自动完成。

外部数据有整理者与训练使用者两种角色，可由同一个人承担。整理者登记、获取、分类和检查；使用者选择任务、用途、本体与配方，在库内找候选并准备训练输入。两种角色不意味着新增首期多人权限系统。

另保留任务负责人视角：固定任务与目标本体后选择自采、公开或购买数据，角色在实际取得、检查、适配和训练步骤中体现。采购现成与委托新采的需求/样本验收见 [专项说明](09_任务驱动的数据选型与采购验收.md)。首期可通过模板与资产记录支持这些工作，不扩展为自动采购或供应商交易系统。

| --- | --- | --- | --- |
| U01 | 建立一个任务项目 | 新建项目，填写任务、目标本体、控制范围与结果判定 | 项目明确区分数据来源机器人和部署目标；未指定动作含义时不能生成训练方案 |
| U02 | 配置与连接设备 | 设备档案、检测连接、保存模板 | 显示设备角色、地址、软件版本、相机和可用能力；缺项用待核实表示 |
| U03 | 准备采集环境 | 准备采集 | 按依赖启动获授权的后台服务；逐项验证，显示人工待办；重复点击不会重复拉起服务 |
| U04 | 启动遥操作 | 启用遥操作、结束遥操作 | 显示控制模式和本次控制的关节/功能；能观察连接、XR 输入、控制状态与退出结果 |
| U05 | 采集一个回合 | 开始录制、结束并保存、标记成功/失败 | 每个回合有唯一标识；保存完成后才出现为可处理输入；失败不默认删除原始文件 |
| U06 | 看清数据质量 | 回合列表、预览、检查、排除/保留、切段 | 报告分清错误、警告、未知与人工结论；预览时能对照图像、state、action 和事件 |
| U07 | 便捷导入外来数据 | 登记地址、读取说明、确认分类、选择下载范围或本地目录 | 可先只登记；提供建议归档位置，区分持有范围、格式、使用条件与缺项 |
| U08 | 整理成可训练数据 | 预览映射、转换、抽样检查 | 先看到输入输出 schema、单位、相机和时间处理；转换不修改原始数据；训练读取检查通过 |
| U09 | 按需增强数据 | 选择增强方式、预览、生成或训练时启用 | 标明视觉增强、重渲染或重新仿真；与母回合共享划分，避免测试泄漏 |
| U10 | 启动并观察训练 | 选数据视图、模型模板、执行位置和运行预算，开始训练 | 显示资源预检、训练状态、输出目录；模型、预处理和数据指纹绑定保存 |
| U11 | 查看策略效果 | 配置评估场景、运行评估、查看结果 | 明确标注回放/离线预测/闭环策略；场景不匹配时不承诺有效成功率；保留全部试验分母 |
| U12 | 把策略部署到设备 | 检查兼容、生成部署包、传输、启用、停止/回退 | 检查动作/相机/控制器/版本契约；传输与启用分开；能确定当前运行版本和控制权 |
| U13 | 少点几次按钮 | 保存流程模板、从某阶段自动运行 | 只消费已完成且兼容的上游产物；人工步骤暂停等待；异常停在失败阶段 |
| U14 | 从故障恢复 | 查看原因、清理本次残留、重试该阶段 | 不覆盖成功产物，不重启无关服务；对状态不明的真实控制操作先核实，不盲目重放 |
| U15 | 了解换设备的代价 | 查看兼容性与适配清单 | 告知哪些能力已接入/仅有公开接口/缺资料；不会因列表存在某厂家就显示“已支持” |
| U16 | 从训练任务选数据 | 选择任务/用途、本体、配方，筛候选、预览并保存视图 | 相关性与训练准入分别显示；以具体组合给出缺项、可执行适配和验证证据 |
| U17 | 重复使用已整理数据 | 复用档案、数据视图与适配产物 | 不反复手填相同信息；来源离线或关键配置变化时显示需复查，不沿用无条件通过结论 |

### 最小完整产品的边界

第一版完整验收范围是**一套固定 G1 配置、一个明确任务、一个遥操作后端、一个导出目标、一个训练算法、一个匹配仿真场景，以及一个受限的部署后端**。G1 准确手型仍待设备确认，当前 43 自由度与 Dex3 的对应是推断；工程启动前要完成清单核对。

完整链路包含设备准备、采集、检查、转换、训练、仿真评价和部署包/受控启用；这些不是只画在菜单上的远期功能。实现可以分段交付，但采集管理完成时只能称为“采集阶段完成”，不能称为“最小完整管线完成”。

数据增强在链路中有明确插入点，可选择跳过；复杂的动力学随机化和自动动作迁移不作为首个 G1 链路的必需实现。外部数据入库与检索复用是并列核心入口：首期至少支持来源登记、本地目录复制/引用、一种已适配 LeRobot 数据源、少量字段分类、任务筛选、视图和组合检查。已接入 Hub 可用成熟接口封装元数据与所选文件获取；跨站全网搜索、自动购买、所有网盘和任意格式自动识别后置。

首期只维护实际使用的本体和训练配方，来源档案可登记更广泛数据。新增训练方法、模型或本体按接口逐项实现与验收，不要求预先支持所有组合。

### 不在首期范围 Non Goals

- 不建设多人权限、机器人集群调度或企业级数据版本平台；保留最小来源、配置和产物关系。
- 不承诺一次适配所有厂商、SDK 和固件版本，不提供“任意机器人立即部署”。
- 不自行重写厂商步态、伺服控制器或商业数采平台。
- 不自动购买数据、租赁云资源、获得厂商权限或跳过设备现场操作。
- 不把一个成功视频、关节范围检查通过或训练收敛解释为自主任务已验证。

## 3 AI 系统需求 AI System Requirements

### 训练与策略组件

策略训练是可替换后端；首期选择一个可在 G1 任务上完整验证的训练方法，例如 ACT，最终选型在匹配数据与环境后确定。Diffusion、VLA、在线强化学习可后续接入，但各自需要训练适配器、预处理和评价条件，不能只给一个模型名称下拉框。

训练后端必须声明支持的数据格式版本、图像 key、state/action schema、时间窗口、归一化、预训练模型条件和设备要求。数据中没有有效动作时，不提供普通监督式行为克隆的启动承诺。在线强化学习还需环境、奖励、终止与交互采样接口。

### 需要集成的工具能力

设备运行器调用已安装的厂商工具/服务接口；采集器提供开始、结束、保存完成与健康状态；导入器读取 Unitree JSON、指定版本 LeRobot 或已约定的厂商格式；训练器提供启动/停止/日志/模型输出；仿真器提供场景准备、策略观察/动作接口、评估与视频；部署器提供兼容性检查、打包、传输、启用与回退。

采集侧的后续扩展按操作者输入、动作映射、本体控制/反馈、相机视频和回合记录划分职责，先包装已有 G1 后端，新增本体逐项适配。可参考 LeRobot 的 Robot、Teleoperator、Camera 划分，详见 [初步调研](08_跨本体遥操作与采集接口初步调研.md)。目前不锁定最终接口签名，也不要求首期实现其他厂家或自研设备。

首期无需增加自然语言自动代理或大模型 API。自然语言选数、自动诊断和流程推荐是可选扩展，不是将现有脚本连接起来的前提。

### 评价方式

软件工作流按设备、阶段和故障注入验收；数据按结构、语义、时间和任务质量验收；模型报告训练/验证/测试表现与简单基线；任务评价用预先固定的场景集合、成功规则、失败分类和接管记录。

用户可用独立的 5 个任务验证界面：建立设备档案；启动一次会话并保存回合；找到并排除缺图回合；用已完成数据运行训练；在评估页分辨回放与闭环。当前未开展此测试，不能声称可用性已验证。

## 4 技术规格 Technical Specifications

### 总体架构

建议分为三层：图形界面；管理项目/设备/阶段作业/产物的编排服务；运行在 Host、机器人侧或训练机上的执行器和厂商适配器。实时控制、超时处理和保护必须留在符合时延要求的本地控制层，不能通过远程网页的请求节奏驱动关节。

图形界面提交意图，编排服务检查依赖后分派作业，执行器报告状态和产物。单人单机器人也要防止两个作业同时占用同一控制权、相机设备或输出目录。界面关闭不应使无人可见的控制任务无限继续；需要显式会话租约、本地看护与厂商认可的控制退出策略。

建议的数据流是：原始来源 → 原始数据登记 → 检查与人工判读 → 划分与筛选 → 可选增强 → 语义适配 → 训练格式打包 → 读取验收 → 训练 → 评估 → 部署。已经是目标训练格式的外来数据可以跳过重新打包，但仍需语义与完整性检查。

### 必须独立的配置对象

| 对象 | 负责什么 | 为什么不能并成一个“机器人型号”字段 |
| --- | --- | --- |
| 目标设备档案 RobotProfile | 厂商、型号、硬件选配、固件/SDK、关节/工具/传感器、控制能力 | 同型号换手、相机或固件，也会改变数据和控制契约 |
| 遥操作配置 TeleopProfile | 输入设备、映射/IK、控制范围、启动/退出方法 | 同一本体可用 Vision Pro、主从臂或其他已适配输入 |
| 数据来源 SourceProfile | 发布/交付方、原始本体、格式/版本、位置、使用条件 | 软件/数据的发布方可能与本体厂家不同 |
| 资产与训练视图 DatasetAsset / DatasetView | 已登记版本、持有范围、回合选择、分类和适用性证据 | 来源存在、文件到齐和当前配方可训练是不同状态 |
| 任务配置 TaskProfile | 场景、指令、采集方式、成功/失败规则 | 搬箱与原地抓放不能共用未区分的成功指标 |
| 训练配置 TrainingRecipe | 数据视图、算法、观察/动作、参数、运行位置 | 共享存储格式不意味着策略接口相同 |
| 仿真配置 SimProfile | 本体资产、场景、控制器、传感器、观察与成功规则 | URDF 存在不等于可闭环评价操作任务 |
| 部署配置 DeploymentProfile | 推理运行时、动作解释器、设备匹配、启停与回退 | 训练输出的动作必须由正确控制接口执行 |
| 流程模板 PipelineRecipe | 阶段顺序、依赖、人工节点、失败规则 | 自动串联需要可核实的阶段输入输出，而非固定延时串命令 |

### 作业和产物规则

每个作业包含稳定 ID、阶段、运行位置、输入产物及指纹、配置快照、状态、日志、输出清单和错误。公共状态建议为：待执行、检查中、等待人工、运行中、停止中、成功、失败、取消、状态未知。运行中和状态未知不能被视为成功。

原始目录只读留存。切段、转换和增强生成新数据视图或派生产物，不覆盖原始证据；不必为每一步复制所有视频。成功产物登记后才可被下游引用。需要持久化，但数据库、前端框架、容器方案和凭据存储实现暂列待定，不能把文档示例当成已选技术栈。

开始/停止录制、启用控制等操作必须核实最终状态。上游若只给 toggle 和“收到命令”的答复，适配器要实现目标状态核对；不能靠重试同一 toggle 实现恢复。

### 集成、凭据与数据使用条件

机器人和训练机用用户配置的连接信息和最小必要权限；密码、私钥、Hub token 不写进流程模板和日志。远程执行只管理本任务注册的服务/进程，不批量结束用户其他服务。下载外来数据前展示大小或未知大小、子集、目的地和来源条件，不默认下载整库。

购买数据导入时要有交付包清单与合同允许用途字段，但工作台不替用户作法律判断。对公开许可证或合同条件不明的资料，展示未知和待确认状态。具有非商业限制的公开数据不能被界面泛称为“可任意商用”。

## 5 风险与路线图 Risks and Roadmap

### 分段实施

| 阶段 | 实际交付 | 阶段验收 | 仍不能声称什么 |
| --- | --- | --- | --- |
| M0 接口与设备盘点 | 固定 G1、训练配方和来源样本；服务依赖、只读探测与模拟执行模式 | 明确支持清单、来源字段与控制副作用；可模拟失败流程 | 尚未实现真实图形采集链路 |
| M1 图形采集与资产登记 | 采集启停、可靠保存与预览；外部来源/目录登记、基础分类与范围状态 | 3 会话，每会话 10 回合；外部登记不默认全量下载，可重复定位已入库数据 | 尚未打通训练与部署 |
| M2 数据处理到仿真评价 | 按任务选数、视图/组合检查、一个导出与训练后端、匹配场景闭环与视频 | 从采集或已适配外部视图实际训练并闭环评价，保存输入和失败证据 | 不能证明已完成真机部署或跨厂家适配 |
| M3 部署与完整 G1 验收 | 部署包、兼容检查、设备启用/停止、版本和控制权追踪 | 在定义的控制范围与任务条件下做真机验收 | 受限抓放通过不代表抱箱行走通过 |
| M4 来源与设备扩展 | 增加下载源与厂商格式、训练方法、本体及相应适配 | 同一工作流驱动新增来源/配方/设备，逐项独立验收 | 资料已登记或接口已预留不等于接入完成 |

M3 结束才叫首个完整 G1 管线版本。M0 至 M2 可以提前提供价值，但应按真实能力命名。设备到货时间、SDK/权限与仿真资产会决定排期，本轮不编造人日或保证完成日期。

### 主要风险及处理方式

- 初始化遥操作进程就接管或改变机器人模式：把只读检查与控制准备分开，按实际源码确认启动副作用。
- SDK 不支持记录完成查询或取消：设计适配层/旁路清单，明确无法实现的状态，而不是伪造完成。
- 外来数据结构兼容但动作含义不明：保留原始语义，阻止以该数据直接生成目标设备部署配置。
- 只有机器人模型，没有场景/视觉/任务评价：界面显示能力边界，不能把关节回放放在“任务成功”栏目。
- SDK/固件版本和商业功能差异：维护明确兼容组合，未知版本先停在检查，不以厂家名字放行。
- 本机高负载影响使用：训练、转换和渲染执行器在运行前及过程中检查资源，保守并发；出现压力只暂停本任务作业。
- 软件管线成功但策略效果差：工作台仍交付完整失败证据，数据和策略改进独立迭代。

### 尚待工程核实的条件

准确的 G1 本体/手型/相机清单；Host 系统与 PC2 软件环境；官方保存完成的可靠观测方式；训练框架及数据版本组合；匹配的 G1 任务场景和控制策略；哪些推理任务运行于 Host、PC2 或独立边缘机。上述条件影响实现细节，但不影响本轮已经明确的产品定位与模块边界。
