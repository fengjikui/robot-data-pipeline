# 从采集到仿真的用户操作与工作台职责

更新：2026-10-31。适用对象：一名研究人员、一台目标机器人，以及与其匹配的仿真环境。

工作台的主要工作，是把设备服务、文件、检查、转换、训练作业和评估结果接起来。用户主要决定任务、判断示范是否符合目标，并决定是否采用一份新数据或一套新配方。日常使用不要求用户理解内部目录、脚本参数、数据契约、随机种子或版本冻结。

## 1. 用户看到四个阶段

**采集或导入数据 → 整理训练数据 → 训练模型 → 仿真验证。**

这四个阶段表达用户目标。质检、转换、增强、划分和后台入库是其中的处理工作，不各自增加一个必须点击的步骤。界面始终回答三个问题：现在在做什么、处理结果是什么、接下来是否需要我决定。

以搬箱子为例，目标仍是从桌 A 抱起箱子、移动到桌 B 并放下。上肢抓取、静止放置或红块仿真均不能直接当作完整任务验收。

转换是让目标训练器能够读取数据，增强是增加适当的变化，两者并非每次都要重新执行。有的图像增强发生在训练读取时，有的仿真生成发生在格式转换之前；工作台按已批准配方安排顺序，用户不手工决定技术步骤的排列。

## 2. 每个环节谁来做

| 环节 | 工作台默认承担的工作 | 用户真正需要做的事 | 何时才打断用户 |
| --- | --- | --- | --- |
| 定义任务 | 记住任务、本体、成功规则和已验证的训练方案；重复实验沿用配置 | 首次说明要完成什么、使用哪台机器人；确认任务成功的判定 | 任务、本体或成功规则发生实质变化 |
| 首次配置设备 | 保存执行机与 SDK 环境，检查版本、目录和服务依赖；生成可检查的启动计划 | 部署者提供环境、地址和设备配置；操作者确认现场设备 | 缺环境、连接失败、版本不符；不能自行猜测本体或手型 |
| 每次准备采集 | 根据已保存配置连接执行器，依序启动或复用依赖并读取状态 | 选择真机或仿真；完成物理准备并点击“准备采集” | 控制模式、头显、相机或仿真场景需要现场处理 |
| 启用遥操作 | 接入已有遥操作程序，呈现随动状态和可核实的输入状态 | 佩戴头显，完成姿态对齐，确认可以随动后启用 | 跟踪、控制权或动作范围无法核实 |
| 录制一个回合 | 自动建立回合目录，记录图像、实际状态、目标动作和任务配置 | 操作机器人；点击开始，以及停止并保存 | 写入失败、记录中断或空间不足 |
| 保存与入库 | 等待记录器完成写入，校验清单，自动传输、登记并排队质检；重试不重复入库 | 正常情况下无需操作，可继续采集下一回合 | 保存或接收失败；显示保留的数据和可重试位置 |
| 技术质量检查 | 自动检查已支持格式的文件、数值、帧索引、媒体引用和来源一致性；保留问题记录 | 只审查无法自动确定的问题 | 缺图、损坏、时间或字段异常；任务语义和标定不足以自动判断 |
| 判断任务结果 | 保存人工标记；有可靠仿真成功规则时附上规则结果和证据 | 标记成功、失败、中断或待判断，可当场或事后补标 | 人工与规则结论冲突，或成功证据不足 |
| 选择训练数据 | 推荐当前任务下、技术检查通过且已确认成功的回合；保留被排除的原因 | 核对推荐范围；需要时排除某回合或保留局部片段 | 新一轮训练输入确认；不要求逐回合反复点击入库、检查和保存 |
| 外部数据入口 | 对已适配来源读取元数据，按用户范围下载或导入，自动识别需要走的处理路径 | 指定来源与任务范围；确认使用条件和无法推断的本体/动作信息 | 许可、动作语义、传感器或本体兼容性不明确 |
| 格式与策略适配 | 按固定适配器映射相机、状态、动作和任务字段，转换后运行目标读取器检查 | 首次由研发者配置并验收适配器；普通使用者选已验证方案 | 缺字段、动作单位或坐标系不明、本体映射未经验证 |
| 数据划分与采样 | 默认按母回合分组留出验证数据；保留划分与来源，防止同源片段泄漏；默认自然采样 | 通常沿用默认值；有实验目的时才调整来源比例或划分 | 数据太少无法留出验证，或指定来源在训练部分没有样本 |
| 数据增强 | 使用已批准配方；生成对照预览和自动检查结果；训练时增强只作用于相应训练部分 | 首次采用或关键参数变化时审查配方与抽样结果 | 改变任务语义、几何或动作；结果不确定。不能默认“加增强一定更好” |
| 整理并固定输入 | 自动保存选择，生成可追溯的数据版本，保留原件和历史；完成后给出简明摘要 | 确认“这次使用这些数据”，无需理解“冻结”操作 | 数据范围、处理配方或关键配置改变，需重新确认 |
| 启动训练 | 检查输入与目标读取器、执行机和资源；填写已验证配方的必要参数，保存日志与模型 | 选择已验证的策略方案，确认资源限制，启动或批准自动继续 | 首次使用配方、显著资源变化、训练异常 |
| 仿真验证 | 加载匹配的本体、控制器、场景与模型；按固定条件运行回合，统计结果并生成视频 | 首次确认任务成功规则；查看结果、决定接受还是补采 | 场景不匹配、模型不兼容、失败或结果证据不足 |
| 失败后的下一轮 | 将失败视频与对应输入关联，提示需要补充的数据；保留上次可复现结果 | 判断补采哪类场景，或让研发者调整方案 | 需要任务层面的判断，而非让用户排查脚本和目录 |

“自动检查”只覆盖已接入和验收的检查能力。当前结构检查不等于完成视频同步、标定、任务成功、策略可训练或部署验收。界面只显示实际得到的结论。

## 3. 日常用户应当怎样走完整条路

### 3.1 开始一轮实验

用户选已有任务和设备。第一次使用才需要填写任务与设备配置。工作台直接说明当前下一步，例如“设备已配置，可以准备采集”，或“还没有数据，可以开始采集或导入现成数据”。

首次配置中的 SSH、Python、厂商仓库和服务参数，放到“设备设置”中，由部署者完成。普通操作者每天不必重新填写。

### 3.2 连续采集

用户点击“准备采集”。工作台连接执行器并按依赖准备服务；有现场待办时明确指出是哪一项。操作者连接头显并核对姿态后，启用随动。

每个回合只保留“开始录制”和“停止并保存”两个明确动作。停止后工作台负责等待保存、接收、登记和排队质检。任务结果可快速标记；无法立即判断时保留“待判断”。

记录器允许下一回合开始时，主按钮恢复为“开始录制”。后台接收和质检优先让出录制资源。用户不需要手工挑目录，也不需要等全部质检完成才能继续采集。

### 3.3 整理这一轮训练数据

采集结束后，用户点击“整理数据”。工作台展示推荐使用的数据、排除项和待判断项，默认配置好划分、采样与已批准的处理配方。

用户主要检查三件事：这些是不是本次任务的数据，成功/失败标记是否正确，有没有需要删除出本轮选择或截取的片段。原件始终保留。

用户确认“使用这些数据”后，工作台自动完成已接入的处理，最后用普通语言报告“已整理多少回合、有哪些未解决问题、是否能被所选训练器读取”。脚本、参数、文件清单和版本号留在详情中。

### 3.4 训练与仿真

用户选择已验证的训练方案与执行机。准备条件满足时启动训练，或使用此前批准的自动流程继续。工作台管理作业、日志、模型与数据的对应关系。

训练结束后，按已确认的仿真方案自动评估，用户主要查看成功率、失败情况和视频。评估必须在匹配的场景中实际闭环运行；单帧预览和离线损失不能充当仿真效果。

仿真通过后，用户决定是否进入下一阶段的真机部署验收。失败时回到有针对性的补采和再训练，形成闭环。

## 4. 默认自动做，哪些地方需要确认

### 无需逐次确认的工作

使用已保存配置连接执行机；复用符合条件的基础服务；建立回合；保存完成后的接收、入库和后台检查；生成推荐清单；自动保存编辑；按已批准配置执行转换和增强；记录日志和来源；对已确认输入执行不改变语义的可重试步骤。

### 默认需要用户判断的地方

- 启动涉及控制初始化的真机程序、启用随动及实际操作机器人。
- 任务成功与失败的语义判断，或审查自动规则的冲突结论。
- 采用一份新的训练数据选择，或改变其来源范围。
- 第一次采用或关键参数变化后的增强、训练或评估配方。
- 资源或任务目标发生重要变化，以及真机部署。

同一对象和同一批准范围不重复确认。改变的是什么、为什么需要重新决定，必须在提示中直接说明。

## 5. 日常界面保留什么

| 默认可见 | 放进“调整设置”或详情 | 不让普通用户手工执行 |
| --- | --- | --- |
| 任务、当前阶段、下一步主按钮 | SSH、解释器、仓库路径与厂商参数 | 拼启动命令、切 Python 环境 |
| 采集状态、录制/保存、任务结果 | 原始 state/action 数组、传感器字段 | 等目录稳定后手工复制入库 |
| 推荐的数据、问题和排除原因 | 来源采样比例、划分和随机种子 | 每个回合分别点入库和质检 |
| 确认使用哪些数据 | 历史版本、输入指纹和文件契约 | 手工创建草稿、冻结版本、构建归档 |
| 训练进度与明确的异常 | 完整日志、转换参数、模型细节 | 把训练输入拼成脚本参数 |
| 仿真结论、失败回合和视频 | 评估条件、种子、逐步指标 | 找模型路径再手工搬进仿真器 |

“自动处理”应自动执行实际操作；单纯把按钮藏起来或换个词不算完成。没有接入的执行能力须显示“待接入”，不能用按钮动画或合成结果代替。

## 6. 当前实现与后续接入分开标注

| 能力 | 当前软件状态 | 实际验收边界 |
| --- | --- | --- |
| 回合预览、标记、手动切段、组合、分组划分与准备包 | 已实现 | 项目读取器验收，不是官方训练器验收 |
| 本地/SSH 采集执行器、录制语义、保存事件、自动入库与后台质检 | 软件接线已实现，合成链路验证通过 | 合成采集用于软件链路测试；真机和 GPU 仿真待工作站配置后联调 |
| 普通本地目录导入 | 已实现 | 手工导入仍有大小上限；采集自动接收走独立受控路径 |
| 指定外部数据来源下载与范围筛选 | 待接入 | 本轮先保留本地导入入口 |
| 官方 LeRobot 转换与目标策略读取 | 待接入 | 项目中间包不能直接称为可训练数据 |
| 增强执行、配方对照与审查 | 待接入 | 方法调研不等于已运行增强 |
| 策略训练与模型管理 | 待接入 | 选择策略不会启动训练 |
| 匹配任务的闭环仿真与视频 | 待接入 | 当前合成采集试运行不是 GPU 仿真评估 |
| 真机部署 | 独立后续验收阶段 | 第一阶段先完成真实训练和仿真闭环 |

## 7. 本轮应验收的用户任务

1. 无真实设备时，用户能明确选择合成试运行，准备、录制、停止后自动看到入库和质检结果。
2. 连接已配置的真机或仿真执行器时，操作路径相同，状态来自实际程序；模式、来源和合成标记不混淆。
3. 用户选好本轮数据后，无需自行保存草稿、生成划分预览或创建内部版本；确认时工作台自动完成这些工作。
4. 默认页面以任务阶段和下一步为主，技术配置和历史信息可查看但不占据主流程。
5. 用户遇到错误时知道哪里失败、数据是否保留、能否重试；重复点击不翻转错误的录制状态。
6. 产品状态明确区分已执行、处理中、等待用户、失败与待接入，不能让“界面上存在”被理解为“完整能力已完成”。
