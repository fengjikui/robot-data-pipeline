# 外部机器人数据资产库与使用流程

更新：2026 年 10 月 26 日。状态：调研与产品设计草案，尚未实现本模块。本文把公开、购买和厂商交付的数据单独梳理，依据真实工具与数据说明提出建议，字段不作为行业标准。本文所说的两类使用者是工作角色，首期可以由同一个人承担，不改变“单人、单机器人”的范围。

补充的任务视角与采购流程见 [任务驱动的数据选型与采购验收](09_任务驱动的数据选型与采购验收.md)：目标本体与任务先固定，分别说明现成数据试用与委托新采，角色标注在实际处理步骤中。采购样本和批次验收结果作为资产库的适用性证据保留。

## 1 产品范围与核心结论

建立一个可重复使用的数据资产库：整理者登记来源、获取所需数据、补充分类与证据；训练使用者从任务出发，在库内找到候选数据，查看与已支持训练组合的差异，准备数据并交给训练器。

实际使用的本体、模型和训练方法数量有限。首期维护一份简短的“本体配置 + 训练配方”支持清单，围绕其中的组合接入数据、保存适配模板和检查记录。新增对象时扩展对应接口并单独验收，不建设自动兼容任意本体、任意模型的平台。

用户提出的任务、模型/训练方法、本体适合作为入口。调研后建议：入口再增加训练用途；底层检查观察/动作语义、时间、质量与覆盖、使用条件和执行位置。**标签帮助发现候选，训练准入依赖特定组合的检查证据。**

## 2 调研依据与设计取舍

| 一手资料中的实际情况 | 对本产品的启发 |
| --- | --- |
| Hugging Face Dataset Card 用说明、许可、任务类别和标签帮助发现数据 [E01] | 保留原始卡片与标签，再映射为本库的小型任务词表；外部标签作为来源声明 |
| Hub 下载工具支持固定 revision 和文件模式筛选 [E02] | 先登记、读元数据，再选下载范围；文件筛选仍需由机器人数据读取器解释 |
| LeRobot v3 中多个回合可共享数值/视频分片，回合位置由元数据解释 [E03] | 库内按回合选数，下载时解析所需实际文件，不能凭文件名猜回合或忽略视频依赖 |
| DROID 提供原始与 RLDS 组织，包含多种状态/命令字段；其处理 schema 还登记场景、成功状态、相机等信息 [E04] | 格式、动作表达与场景分开登记；支持回合级筛选，保留字段证据和原始记录 |
| Open X-Embodiment 统一组织多个数据源，动作解释仍取决于来源控制方式 [E05] | 支持多来源集合并保留子来源；统一容器不能成为本体动作通用的证明 |
| OpenVLA 与 openpi 的参考实现有各自读取和预处理路径 [E06][E07] | 管理具体训练配方与适配模板，避免只给数据永久勾选“支持 VLA” |

以上为资料事实；以下用户流程、字段和验收方案是本项目设计推论。首期不照搬所有公开字段，也不采用一个不透明的综合推荐分。

## 3 使用者眼中的“数据库”

界面统一称为“数据资产库”，内部允许将说明和索引与大文件分开保存，具体数据库和存储产品暂不选定。

| 库里管理什么 | 用户看到什么 | 与其他对象的区别 |
| --- | --- | --- |
| 来源条目 | 哪个网站/发布方/交付方、地址和说明 | 可以只登记，尚未下载 |
| 数据版本与入库范围 | 取得哪一版、哪些回合/文件、存在哪里 | 同一来源可以只获取任务相关子集 |
| 数据视图 | 本次保留哪些回合/片段、用于何种划分 | 通过选择清单引用原始数据，通常不用复制视频 |
| 派生训练数据 | 从哪个版本经何种适配产生、供哪个配方使用 | 转换成功不修改原始数据和原有解释 |
| 适用性记录 | 对某任务/本体/配方，缺什么、处理过什么、验证到哪里 | 结论有条件和证据，不能作为无条件通用标签 |

因此“本库有这个数据集”要细分为仅登记、少量样本、部分回合/文件、所选范围完整。若整库范围未知，界面不显示“全库完整”。实际已下载的数值、图像和元数据分别登记，只有数值分片时不显示为视觉训练数据完整。

## 4 数据整理者的使用流程

| 步骤 | 用户操作 | 系统帮助做什么 | 得到什么 |
| --- | --- | --- | --- |
| 找到或接收数据 | 在网站找到来源，或收到硬盘、网盘/下载链接、共享目录 | 可粘贴仓库地址、选本地目录；已接入来源可从目录页搜索 | 来源草稿，暂不默认全量下载 |
| 读取说明与预览 | 点击“读取元数据” | 识别已支持格式，提取发布方、版本、任务和特征，展示样本/文件树 | 自动提取内容与未知项 |
| 补充少量分类 | 确认任务技能、原始本体/工具、来源方式与用途说明 | 使用模板、搜索选项和批量应用，区分外部标签与本库标签 | 可检索的数据档案 |
| 选择获取范围 | 仅登记、取样本、取任务子集或指定文件 | 预览所需文件、依赖、预计大小/未知大小与目的地 | 本次下载/导入清单 |
| 导入已有数据 | 选择复制入库或只读引用已有目录 | 自动建议归档位置，检查重名和可复用文件；不强迫用户手工整理每个子目录 | 受管文件或带依赖说明的目录引用 |
| 检查与登记 | 点击“检查并入库” | 核对所选范围、可读性、有效字段、回合索引，记录问题与检查范围 | 入库结果、预览和待补材料 |
| 准备已支持组合 | 选择已有本体与训练配方，点击“检查适用性” | 对照契约列出可用项、缺项和可执行适配计划 | 带版本和证据的组合记录 |

首次只要求用户确认关键缺项；相同格式和交付方可复用导入模板。机器抽取不能确认的字段保留未知，允许先登记、稍后补齐；满足训练条件之后才开放对应训练准备。

### 获取与归档的实际边界

- Hugging Face 可封装已支持的元数据查询、固定版本和文件下载能力。按任务/回合下载要由读取器解析回合到文件的依赖，不能把通配符筛文件等同于任务语义筛选。
- 通用网盘和购买交付首期允许先人工下载，再选择本地目录；取得稳定接口后再增加专用下载器。失效链接或不可用认证作为待办，不声称所有网盘均已自动接入。
- 复制入库便于长期使用；引用移动硬盘能减少复制，但拔盘后要显示“来源离线”。保存盘/卷标识和可重新定位信息，重新连接后核对清单。复制不是移动，不删除交付原件。
- 同一发布方/仓库、版本和文件内容可帮助识别重复；同名不表示同内容。复用物理文件时仍保留不同来源和使用条件记录，大文件检查可分批进行。
- 只登记元数据可以先完成。抽样检查结果写明“检查了哪些样本”，不能变成全库全部通过；下载/复制未完成的目录不作为完整训练输入。

## 5 训练使用者的使用流程

使用者首先创建训练任务，选择任务目标、训练用途、一个已登记的目标本体配置和一个已支持的训练配方。系统带入该配方需要的相机、状态、动作和时间要求，用户不用从头填写技术表格。

| 步骤 | 用户操作 | 系统展示/产出 |
| --- | --- | --- |
| 查找 | 点击“为本任务选数据” | 先查内部资产库；按任务技能、来源、本体、模态和可用状态筛候选，可切换显示未下载或待适配条目 |
| 判断 | 查看候选与当前组合的差异 | 相关技能与缺失阶段、输入/动作差异、使用条件、实际获取范围和已有验证记录 |
| 预览 | 看几个代表回合和质量报告 | 图像、状态/动作、任务文本、成功/失败及检查范围；不只看标题或一个标签 |
| 选择 | 选回合/片段、多个来源和数据划分 | 保存有名字的数据视图；展示来源、是否重复、场景/采集组和评估集冲突 |
| 准备 | 点击“准备训练数据” | 补取必要文件，执行已支持适配，读取验收，保存配置与产物；遇到缺项停在具体步骤 |
| 开始训练 | 确认读取验收和执行位置 | 训练器得到稳定的数据版本、视图和配方；远端训练前确认数据可达或展示待传输计划 |
| 重复使用 | 再次选择已保存视图或模板 | 条件未变时复用数据与适配产物，重新核对可用性；条件变化时说明需要重查哪些项目 |

“不用再去网上找”首先意味着：团队已经整理过的数据可以在库内发现、比较和复用。找不到候选时，提供“登记新来源/提交待补数据”入口，不凭空推荐不存在的已入库数据。

## 6 从哪些维度判断适用性

任务、本体、训练方法是主要条件，训练用途决定这些条件要严格匹配到什么程度。筛选入口保持简短，详细检查在后台和详情页展开。

| 维度 | 使用者的问题 | 实际检查与反馈 |
| --- | --- | --- |
| 任务与覆盖 | 数据包含我需要的操作吗？ | 区分物体、技能和完整流程；抓箱子与负载移动分别标注，说明还缺哪些阶段/场景 |
| 训练用途 | 本次用它做什么？ | 目标任务监督训练/微调、较广泛的预训练、表征或感知学习、离线分析/评估等；哪些用途开放由配方支持清单决定 |
| 本体与控制范围 | 数据来自什么设备，准备驱动什么？ | 来源与目标分别记录；精确到手型、工具、受控关节/底盘及控制方式，未知不能当匹配 |
| 训练配方 | 当前训练器实际需要什么？ | 实现和版本、输入特征、动作输出、语言要求、历史/预测窗口及归一化；仅模型名字相同不够 |
| 观察与动作语义 | 保存的量究竟表示什么？ | 相机身份与布局、关节顺序、单位/参考系、绝对或增量、实测状态与目标命令；区别有效数值与空字段 |
| 时间与数据完整性 | 能组成有效训练样本吗？ | 采样与对齐、缺帧、回合边界、必要文件和解析能力；格式可读与物理同步分别显示 |
| 质量与泛化 | 数据质量、场景和数量是否适合本次实验？ | 成功/失败与人工标注、场景变化、有效时长、重复回合、采集批次与划分；数量大不自动得到较高适用等级 |
| 使用条件与可达性 | 本次用途和执行环境能否使用？ | 展示来源条件原文和待确认项；检查本地/远端文件是否可达、所需数据量/存储是否已知 |

训练用途不是给每个数据集强制规定一个唯一类别。数据可以在一个配方中做直接示范，在另一个研究中做预训练候选；候选价值不等于已验证效果。以 DROID 和 G1 为例，来源设备不同并不妨碍研究跨本体预训练，但直接输出 G1 控制动作必须经过相应动作与控制验证。

## 7 字段、枚举与标签怎样组织

以下为建议词表。固定枚举用于稳定类别，注册表用于实际设备/配方清单，数值与原文按实际值保存。自由标签补充细节，关键训练条件使用结构化字段。多来源集合可有“混合”汇总，训练选用的回合仍保留其准确来源属性。

| 字段组 | 类型与初始选项/示例 | 谁来填写 | 首期安排 |
| --- | --- | --- | --- |
| 取得性质 | 固定枚举：公开发布、购买交付、合作共享、内部自采、其他、未知 | 来源说明 + 用户 | 与通过网站还是硬盘取得分开记录 |
| 来源方式 | 固定枚举：Hub/网站、厂商下载、网盘、硬盘交付、共享目录、已有本地目录、其他、未知 | 自动识别 + 用户确认 | 必须登记；与发布方分开 |
| 身份与版本 | 发布方、来源地址/交付批次、源版本或清单指纹 | 自动提取/交付资料 | 必须有来源和版本依据；网址变化不替代文件身份 |
| 采集来源 | 固定枚举：真机、仿真、混合、人体/视频、未知 | 原始说明 + 样本核对 | 允许未知；人体视频不自动标为有效机器人动作 |
| 任务技能 | 多选受控词表：抓取、放置、双臂协作、抱持、负载移动、导航、开合、装配、其他/待分类 | 用户确认；可映射原标签 | 按当前任务先用少量词；“搬箱”可组合技能 |
| 物体和场景 | 可选标签/词表：箱体、餐具；桌面、仓储、室内等 | 原始说明 + 用户 | 首期可选，保留具体任务原文 |
| 原始本体 | 本体档案注册表 + 公开来源原文/未知 | 模板/来源元数据 | 可登记未接入来源设备，不使其变成可部署目标 |
| 手部/工具与控制范围 | 档案值；类型可用夹爪、灵巧手、吸盘、其他、混合、未知 | 模板 + 用户 | 初期只精化实际使用的配置 |
| 模态 | 多选：RGB、深度、关节状态、语言、力/触觉、IMU/移动状态、其他 | 读取器提取 + 检查 | 区分声明存在、文件存在和样本有效 |
| 格式与版本 | 已接入读取器注册表；例如 LeRobot、Unitree JSON；其他格式保留原文/待适配 | 读取器 | 不因文件是 HDF5 就推定内部语义 |
| 处理与派生层级 | 原始采集记录、已整理/标注轨迹、指定配方训练输入、混合、未知 | 来源说明 + 处理记录 | 与容器格式、质量和适用性分开；可有多层产物，“训练输入”绑定配方/视图 |
| 动作表达 | 分组结构：关节位置/增量、速度、力矩、末端位姿/增量、移动速度、复合、无、未知 | 模板/样本/文档核对 | 同时保存顺序、单位和参考系；不是一个维数字段 |
| 时间和规模 | 频率、相机时间信息、回合数、帧数、有效时长、字节数 | 读取器/检查 | 数值和未知值，不为所有数字建立枚举 |
| 标注与质量 | 成功/失败/中止/未知；检查报告指针与覆盖范围 | 原始标注/人工/检查 | 标签含义和来源可追溯；不设未经验证的统一 A/B 质量等级 |
| 使用条件 | 来源原文/许可/合同引用；待补说明、已登记说明、需确认等记录状态 | 导入者确认来源 | 显示已知条件和缺项，不自动作法律用途判断 |
| 组织与持有状态 | 项目/集合、管理人、存储位置；仅登记/样本/部分/所选范围完整；在线/离线/未知 | 系统 + 用户 | 不把“已登记”计入可训练文件量 |
| 目标适用性 | 数据视图 × 本体配置 × 训练配方 × 用途的检查记录 | 系统检查和实验 | 不是可手工随意勾选的永久“通用/专用”标签 |

标签写在数据档案中，归档目录由系统建议；改“搬箱”标签不移动所有原始文件。同一数据可属于多个项目/集合，通过视图复用。对象尺寸、重量、相机标定等若对配方重要，保存为有单位的值或文件引用，不能用模糊标签替代。

报告中的快速介绍把 JSON+图像/视频、HDF5/Zarr、录包，以及 LeRobot/RLDS 等作为常见保存/组织方式举例，不把它们划成互斥的同层标准。处理层级说明数据经过哪些工作，不能代替读取检查或任务适用结论；列出某个格式也不代表本平台已接入它。

### 避免导入时填一大张表

来源地址/目录选定后，先提取可获得的元数据。整理者优先确认：来源说明与版本、任务/技能、原始本体、用途条件、入库范围和位置；相机、维度等由模板与读取器带入并标出来源。高级时间/动作配置在检查出差异时再展开，缺关键语义的数据允许入库待补，但不放行相关训练。

外部原始标签保留；本库的受控标签可纠正和细化。每项重要属性区分“来源声明”“文件/样本检查”“人工确认”，适用性另附读取/训练/评估记录。项目推断不得覆盖原始字段变成无来源事实。

## 8 适用性结果与转换操作

界面不要只问“这个数据通用吗”，而应回答“对当前选定组合，可完成到哪一步”。

| 用户可见结果 | 表示什么 | 下一步 |
| --- | --- | --- |
| 当前配方输入检查通过 | 对所选视图、版本与配方，结构和已定义语义检查通过 | 准备或复用训练输入，启动训练；任务效果另评估 |
| 有已支持适配步骤 | 明确缺项可以由已有模板处理，尚未完成处理验收 | 预览变换与信息损失，执行后重新读取检查 |
| 仅作特定预训练/研究候选 | 当前直接执行契约不匹配，但选定研究配方允许该用法 | 进入对应实验流程，标注未验证收益 |
| 缺材料或需新适配 | 动作、时间、相机等条件未满足，或缺少实现 | 显示具体材料/适配待办，保留档案与预览 |
| 未评估 | 尚未针对当前组合检查 | 运行适用性检查，不默认可用或不可用 |

另外保留验证进展：元数据核对、样本读取、训练运行、匹配场景闭环、指定真机范围。读取通过不替代训练测试，训练完成不替代任务效果；不能用“数据被训练器加载过”给机器人显示可部署。

### 按钮与自动化边界

用户看到的是“读取说明”“检查并入库”“检查适用性”“预览适配”“准备训练数据”“启动训练”，不需要手动管理每个底层格式脚本。可选择对满足条件的数据自动串联，遇到关键未知项等待处理。

| 可以做什么 | 自动化条件与边界 |
| --- | --- |
| 元数据、格式和文件读取 | 来源与读取器已接入；无法辨识时保留原文/未知 |
| 下载、复制、清单与归档 | 范围和目的地确定，接口可用；不默认整库下载或改写交付文件 |
| 字段/单位映射、训练格式打包、时间窗与训练集统计 | 使用已核对语义的固定模板；输出后实际读取验收 |
| 动作表达转换 | 在已定义参考系、运动学/标定和时序条件下执行已实现变换；不能一般性保证关节与末端、绝对与增量互相无损 |
| 跨本体、手型与控制方式迁移 | 需要具体迁移方案、新数据或算法及验证；只开放已验证范围，不用补零/重命名伪装为新本体动作 |

适配结论绑定源版本/文件清单、回合视图、目标本体配置、训练配方和转换配置。任一关键项变化时标记需复查；原始数据、旧视图和历史结果仍可追溯。首期只需清单和配置快照，不引入大型版本平台。

## 9 搬箱任务的三个使用例子

以下是判断方式示例，不是本轮新完成的训练结论。

| 候选数据 | 能帮助什么 | 当前还缺什么 |
| --- | --- | --- |
| 已核查的 G1 Dex3 烤面包公开数据，现有本地仅数值分片 [E08] | 同配置数值读取、关节动作训练实验、管线检查 | 完整视觉实验需相应图像；任务技能/场景与搬箱有差异，普通手臂数据也不覆盖负载行走 |
| DROID 操作数据 [E04] | 外来数据导入研究、所选配方下的操作预训练候选 | 具体动作字段与视角要核对；来源本体与 G1 不同，不能按同向量长度直接驱动 G1 |
| 供应商交付的“箱体搬运”数据包 | 若覆盖目标阶段，可成为更接近任务的候选 | 需取得原始本体、受控范围、动作/状态、时间与相机说明和样本检查；标题与供应商标签不足以判断 |

同一个 G1 任务可以组合不同用途的数据：一部分用于预训练，一部分用于目标任务微调，独立留出回合/场景评估；组合方案由训练配方明确规定，不能把异构数据直接拼接成一套无差异动作标签。

## 10 有限支持清单与新增接口

用户只从已启用的目标本体和配方里选择，来源档案则可以更广。尚未接入的来源设备可登记为来源，不必立刻购买或支持控制它。

首轮建议固定 G1 的准确选配、一个训练配方和一种已知机器人数据格式，先完成“登记/导入、分类筛选、预览检查、训练视图、准备与复用”。ACT 可作为候选，最终以现有任务、数据和环境确定；VLA、PPO 等留作后续独立接入。支持清单不要求预先实现所有本体与模型的笛卡尔积。

| 以后新增什么 | 需要扩展什么 | 对使用者的变化 |
| --- | --- | --- |
| 一个下载来源 | 来源解析、认证/获取与清单能力 | 多一个可粘贴/搜索并导入的入口 |
| 一种数据组织 | 元数据、回合、样本读取和特征说明 | 能预览和检查该来源，再按已支持目标评估 |
| 一种适配路径 | 声明输入前提、转换输出、配置和验证范围 | 差异页出现可执行处理步骤 |
| 一种模型/训练方法 | 训练配方与样本契约、加载验收、训练/输出接口；需要时加环境接口 | 配方列表增加经过验收的选择，不自动变为所有数据都适用 |
| 一个目标本体 | 设备/动作档案、控制、仿真和部署接口，及适用性规则 | 目标设备列表增加选项，原数据仍保留来源本体 |

先在已知工具之间做简单、明确的后端注册即可；无需首期开发可热插拔插件市场。每项能力分开标注文档声明、已接入和已验证，新增实现不会自动使历史数据得到新通过结论。

## 11 建议页面与首期验收

主要页面包括：来源目录（可未下载）、导入向导、资产详情与回合预览、按任务选数、适用性差异与准备作业、训练视图。主入口保留任务、本体、配方、用途和少量常用筛选，其余信息按需展开。

首期验收使用少量已知数据与故障样例，以下是拟执行目标，尚无可用性测试结果：

1. 整理者只登记一个来源时不下载大数据，之后取样本再扩充子集，界面能准确区分各自范围。
2. 对同一来源重复导入不重复创建无关联副本；本地目录或硬盘引用离线时显示原因并能重新定位。
3. 使用者从“任务 + 一个本体 + 一个配方 + 用途”找到候选、预览、保存视图并准备数据；下次可直接复用，条件变化可追踪。
4. 缺图、未知动作语义、格式可读但目标契约不匹配的样例能得到不同说明，不被“相关标签”误判为可直接训练。
5. 在已支持组合上实际运行读取验收与训练，保存输入视图、配方和结果；预训练候选与目标任务已验证数据分别展示。

可在小规模数据导入迭代中再观察用户填写时间、重复配置次数和需要打开外部终端的次数，决定删减哪些字段。当前不编造节省时间、搜索精度或通用适配率。
