# 开发工作包与验收映射

更新：2026-10-26。阶段编号以[整体方案](10_整体方案与产品价值_2026-10-26.md)为准。当前 v0.1.2 是基础数据准备原型；下面除明确注明的基础能力外均是待开发。

## 1. 开发对象与接口边界

| 共享对象 | 最小内容 | 为什么需要 |
| --- | --- | --- |
| TaskProject | 总目标、本轮范围、成功规则、目标设备/配方、选定视图 | 保留使用意图，不把它写成来源数据事实 |
| DeviceProfile / TeleopProfile | 精确选配、SDK/固件、输入、控制、相机、网卡、首次检查记录 | 复用配置，区分只读与控制准备 |
| SourceEntry / DatasetAsset | 来源、revision/批次、原始任务/本体、许可引用、持有范围、文件清单 | 来源登记不等于数据已到齐 |
| DatasetView | 回合选择/切段、排除原因、训练/验证划分、母子关系 | 不为每次选数复制整库，降低数据泄漏风险 |
| CompatibilityCheck | 目标组合指纹、检查项/证据、差异、支持的处理步骤 | 判断当前组合适用性，不设永久“通用”标记 |
| Run / Artifact | 阶段、执行机、输入/配置快照、日志、状态、完成清单与哈希 | 支持失败恢复、追踪与复跑 |
| ModelBundle / Evaluation | 权重、预处理/统计/动作接口、场景与指标、视频、验证范围 | 训练完成不等于任务成功或实机可用 |

首期沿用现有存储和作业结构增量扩展，先加清单与关联，不为未来多用户引入复杂权限、分布式调度或通用图编辑器。

存储分为三层：目录/对象存储保留原始媒体和派生产物；目录索引保存来源、范围、标签与文件清单；任务视图只保存回合引用、选择和划分。资产库不意味着把所有视频塞进同一个数据库。归档位置由工作区规则建议，用户改标签不搬动整库，正式产物用稳定ID与受管理相对路径关联，执行机上的实际位置另行解析。

## 2. 可拆分工作包

| ID / 阶段 | 工作包 | 前置与输出 | 验收场景 |
| --- | --- | --- | --- |
| F01 / 立即 | 现有表单与状态纠正 | 来源任务独立；输入限制统一；切换详情加载态 | 外部数据不被自动标成目标任务，旧作业链接不串到新资产 |
| C01 / M1 | 设备档案与只读预检 | 精确设备配置、检查项、结果/时间、待人工项 | 模拟连接失败、版本不匹配与状态过期；预检无控制发布 |
| C02 / M1 | Host采集桥与模拟实现 | 状态查询、受限启停、回合完成事件、进程归属 | 成功/超时/断连/重复点击；模拟始终可辨认 |
| C03 / M1 | G1真实服务编排 | PC2相机、Host IPC与XR待办；复用已有基础服务 | 单设备失败仅重试该项；退出只清理本次启动的进程 |
| C04 / M1 | 录制状态与保存完成 | 可观测会话状态、保存完成manifest、资产入库 | ACK丢失不重发toggle；文件未完成不入库；每次会话10回合 |
| D01 / M1 | 外部来源与资产基础编辑 | 网址/本地清单、原始元数据、用户确认与持有范围 | 只登记不下载；样本与完整范围区分；重复使用找回同资产 |
| D02 / M1–M2a | 回合预览与分层检查 | 图像/state/action/时间对照，问题定位和排除视图 | 结构、时序、标定、任务结论分别显示未查/通过/问题 |
| D03 / M2a | 一个有限来源获取器 | 固定revision、范围、目的地、清单/哈希、空间预检 | 中断后不重复成功文件；离线/权限/限额可理解，不默认整库 |
| D04 / M2a | 数据视图与适用性矩阵 | 任务/本体/配方组合，差异和处置，配置指纹 | 缺关键语义阻断；改配方只标受影响检查为需复查 |
| P01 / M2b | 官方转换与首个读取器 | 固定依赖、字段/动作/相机模板、训练划分和统计 | 实际后端加载一批样本；维度相同但动作语义不同仍拒绝 |
| P02 / M2b | 按需增强/切段 | 先预览、母子关联、原件保留、划分继承 | 同母回合及其派生不跨集合；视觉增强不改错动作含义 |
| T01 / M2c | 一个训练与仿真后端 | 数据视图/配置/执行机/预算绑定，产物清单 | 真实训练和匹配场景闭环；失败保留日志、视频和中止结果 |
| R01 / M1–M3 | 执行与恢复基础 | Run/Artifact契约、状态对账、有限重试、资源检查 | 断网刷新后找回作业，不重试有控制副作用的未知动作 |
| V01 / M3 | 受限部署与回流 | 模型包、设备匹配、控制范围、实机记录与补采待办 | 模型/统计/控制接口不匹配时阻断，固定范围现场验收 |
| X01 / M4 | 第二个来源/配方/本体 | 分别扩展适配器，保留共享页面与作业语义 | 对新增具体组合独立验收，文档兼容不冒充运行通过 |

## 3. 跨平台验收矩阵

| 对象 | Windows / macOS / Linux工作台 | 实际执行环境 |
| --- | --- | --- |
| 管理服务、路径、资产和记录 | 原生测试、干净安装、中文/空格/相对路径、旧工作区恢复 | 当前已有基础CI；新模块继续增加对应契约测试 |
| 系统目录选择 | 交互桌面确认/取消，Linux缺桌面可手动输入 | 不能把CI实例化组件当成GUI点选 |
| Host/PC2采集桥 | 相同协议与状态展示 | 按厂商SDK支持系统验收，不承诺厂商脚本全平台运行 |
| 转换/训练/仿真 | 配方与执行机显式选择，日志/产物位置明确 | Linux/GPU或其他经过验证的资源；先核实现有算力、环境与负载，不预设云租赁或某类加速器 |
| 大数据导入与下载 | 清单、范围、空间和恢复语义一致 | 读写/缓存路径在执行机上，不用客户端路径冒充服务器路径 |

高负载运行前及过程中检查负载、可用内存和可取得的热状态，保守并发，压力升高时降负载或暂停，只管理本任务进程。测试使用独立工作区，不把演示样例放入正式启动。

## 4. 设计评审清单

- 新用户能否在首屏说出当前任务、本轮范围、当前阶段和下一步？
- 第一次与重复使用是否不同？复用项是否足够，变化项是否重新核实？
- 来源事实与目标意图是否分开，标签是否被错误当成可训练证据？
- 操作前是否知道在哪里执行、改动什么、得到什么？
- 正在保存、已完成、失败和状态未知能否清楚区分？
- 失败是否保留输入和已成功产物，能否只重试失败阶段？
- 同一数据换配方/本体后能否准确指出需要复查的部分？
- 增强、切段、统计和划分是否可追溯，有没有同源泄漏？
- 页面刷新/切换后，是否还能定位原作业且不显示其他资产的旧结果？
- 演示原型、自动测试、真实联调、模型效果是否分别记录？

本轮交付文档与可点击原型不修改生产工作台执行能力。开发时先选一个工作包，落实接口和验收场景，再接通界面，避免一屏按钮先行、后端状态缺失。
