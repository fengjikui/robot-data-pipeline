# 跨本体遥操作与采集接口：初步调研

更新：2026 年 10 月 26 日。范围：说明平台要解决的采集扩展问题、可参考的开源划分与大致接入思路。本轮不实现通用控制器、接口 SDK 或新本体驱动，也不承诺已兼容所列设备。

## 1 需要解决的问题与用户价值

G1 的采集链路依赖特定的头显、映射程序、机载服务、状态/命令接口与记录器。以后换机械臂、宇树另一型号、智元、银河通用或自研机械结构时，这些环节可能变化。

使用者希望继续沿用“选择设备配置、准备环境、预览、启用遥操作、录制回合、结束保存、查看数据”的操作方式。平台通过采集适配后端组织具体设备工具，减少每换一种本体都重新设计操作入口、目录管理和后续数据处理的工作。

实际采购与使用的设备数量有限。先固定 G1 的一套组合；新增本体时增加并验收该组合的后端，保留相同的上层会话与数据管理。这里统一的是操作生命周期、能力声明与有明确语义的数据接口，动作维度、控制模式和输入设备按组合配置。

## 3 采集层建议分开的职责

| 部分 | 通用层向使用者提供什么 | 新本体或输入方案要适配什么 |
| --- | --- | --- |
| 操作者输入 | 检查头显/主从设备/控制器输入是否就绪 | 输入协议、追踪/标定、按键与反馈；本体与输入设备分别选择 |
| 输入到目标动作的映射 | 显示可控制范围与配置 | 按具体机构做坐标变换、缩放、关节对应、IK 或手部重定向；按需选择这些步骤 |
| 本体状态与控制 | 读取反馈、启用与退出指定控制 | SDK/通信协议、关节/工具语义、控制频率、控制权及本地超时行为 |
| 相机与视频接入 | 选择、预览和记录所需视角 | 本机相机或已有视频服务、身份/分辨率/帧序、可获得的时间信息与标定 |
| 回合记录 | 开始、结束保存、标注结果、登记产物 | 对接厂商记录器或已有记录程序，确认字段和完成条件；需要时增加记录层 |
| 会话与服务组织 | 检查依赖、启动/复用服务、报告状态和恢复入口 | 服务在哪里运行、如何探测、哪些需现场操作、正常退出和清理范围 |

这是一份职责清单，不要求首期拆成六个独立服务。已有厂商工具内部把多项能力合在一起时，先用一个适配桥包装其可观察入口；缺少接口的地方明确列出缺口，后续再决定扩展上游或补组件。

### 视频接入还需表达什么

预览画面和训练记录流可能有不同传输路径、分辨率与缓存。适配后端应分别说明每路相机的身份、实际使用的数据流、帧序、新鲜度、可取得的源时间/接收时间和时钟说明；缺失项标记未知。

录制时仍要检查图像、状态与动作的对应关系。统一读帧接口不自动实现物理同步，名义时间轴也不能替代缺失的采样时间。已有协议或框架可在适配器内部复用，当前不强制所有厂家改成同一传输协议。

### 控制与记录还需表达什么

声明实际关节/工具、单位和参考系，分开记录实际状态与目标动作。有条件时再区分映射生成的目标、约束后的已发送目标、设备回执和实际反馈；没有回执时不声称命令已执行。

连接/初始化可能包含标定、配置或模式切换；方法叫 `connect` 不保证只读。平台的只读检查、控制准备、跟随与录制应有可观察状态。正常退出也不能被标为通用硬件急停，本地实时控制与失联处理依赖具体设备后端和已验收方案。

## 4 新增本体需要提供什么

新增后端至少提交本体/软件配置、可用能力、状态与动作说明、输入映射、相机与时间信息、服务启停和记录完成依据。缺某种能力时，界面显示不支持或待补，不给所有设备展示同一组可用按钮。

- 换宇树型号：核对已有控制类、手型、关节和记录范围，能复用的模板继续用，缺失处增加适配。
- 换机械臂：对接控制箱/SDK、夹爪、外部相机和适用输入映射；不为固定臂伪造行走能力。
- 换智元或银河通用：按具体交付产品/版本接 SDK 与已有采集工具，先取得程序化接口和样本，不以厂家名字判定整条链路支持。
- 自研本体：先提供可程序化读取传感器与发送命令的接口，以及运动学、标定/限位和退出条件，再接入相同采集流程；平台不会自动从机械外形生成可靠控制。

验收由浅入深：配置与模拟后端、只读观察/视频、指定范围控制、完整回合保存、接入后续检查。第二种本体接入后，才能用实际证据说明上层采集流程的复用程度。

**采集适配与已有示范的跨本体迁移是两项工作。** 能遥操作新设备并录到它自己的数据，仍需单独验证旧 G1 数据或旧模型是否适用于它；后者沿用资产库中的组合检查和迁移方案。

## 5 在本次报告中怎样讲

纳入后半部分 B5，不新增投影页，讲约 40–60 秒，正文只保留：

1. 问题：换本体时，遥操作、视频和记录链路都可能变化。
2. 思路：上层采集操作保持一致，下层分别接入操作者输入、动作映射、本体/相机与记录后端。
3. 范围：先封装 G1，后续按实际新增设备逐项适配与验收；包含自研本体的接口方向，不声称当前已支持。

配图建议：上方一条“准备、预览、遥操作、录制、保存”的通用流程，下方示意 G1、机械臂、其他/自研本体的采集后端；用标注区分首期目标与扩展方向。厂商/型号详表、API 方法名和时钟细节留备查。

正式讲稿可围绕这句话展开：“我们希望更换机器人后，使用者仍能沿用同一套采集操作；需要替换的是该设备的控制、输入映射、图像与记录接入。先把 G1 做实，再检验第二种设备能复用哪些环节。”当前仅为讲述要点，完整逐页讲稿后续制作。
