# 自行采集 开源数据与购买数据的接入流程

本文件说明工作台为什么需要多种入口，以及“转换”应拆成哪些不同工作。它是需求设计，未实现新的下载器、数据适配器或跨本体迁移算法。

2026-10-26 补充：来源登记、导入归档、字段/枚举、任务选数和适用性证据的完整用户流程已单列为 [外部数据资产库与使用流程](07_外部数据资产库与使用流程.md)。来源条目可以未下载，资产库围绕少量已选本体和训练配方逐步接入。

## 三类入口 不等于三套下游程序

| 入口 | 用户首先提供什么 | 工作台首先处理什么 | 何时进入共同下游 |
| --- | --- | --- | --- |
| 真机/仿真自行采集 | 任务、设备、采集与存储配置 | 多设备服务、遥操作、记录、结束与保存、回合标注 | 原始回合完成登记，来源和语义已知 |
| 公开数据 | 目录条目、数据仓库 URL 或已有本地目录 | 来源/版本、许可与下载范围、文件读取和源本体/任务辨识 | 文件完整且来源/格式/动作语义达到要求 |
| 购买或厂商交付数据 | 交付目录/数据包、清单、schema、用途条件 | 包完整性、字段与单位、时间和相机/工具说明、交付条件 | 已取得可解释的数据及所需条件，缺项明确标出 |

来源登记之后，大家共享“原始数据 → 数据视图 → 质量判读 → 训练输入 → 模型 → 评价 → 部署”的产物关系。入口差异由 SourceAdapter 和采集适配器吸收，而不是让用户学三套界面。

## 搜索与下载实际需要哪些功能

首期不做全网自动抓取和自动购买。来源页先提供少量人工核实的目录，可按任务、本体、手型、是否含动作、传感器、格式版本与使用条件筛选；用户也可以粘贴已知仓库地址或选择目录。

一个目录条目至少包含：发布方、原始本体、任务、数据/文件格式版本、特征概览、是否含有效动作及语义、频率、相机、大小/大小未知、下载地址、revision、许可或合同说明、是否有对应场景和示例读取器、核查日期。条目中的“适合当前任务”需要列出依据和差异，不能只显示推荐分。

下载前预览具体子集和目的地；支持进度、暂停/续传（后端支持时）、完整性校验、失败重试和避免重复下载。大数据默认先取元数据与少量回合，不因为用户点击来源条目就拉取整库。认证信息保存在受控凭据入口，链接和运行日志不带 token。

公开可下载不代表原始数据足够训练，也不代表适合当前用途。比如本轮查阅的 AgiBot World 2026 数据卡有自己的非商业等使用条件；具体条件与来源快照一起登记，不把“开源”当成统一授权。[R09]

## 导入后至少拆成六个判断层次

| 层次 | 真正完成什么 | 示例 | 不应宣称什么 |
| --- | --- | --- | --- |
| 1 获取与解包 | 文件能完整到达并读取 | 厂商压缩包、Hub 分片、已有目录 | 文件到齐就等于可训练 |
| 2 容器/格式读取 | 解释 JSON、HDF5、Parquet、视频、rosbag 的结构与版本 | Unitree JSON 的图片路径；GenieSim 后处理 HDF5 | 能读 HDF5 就理解了其中 action |
| 3 字段与时间标准化 | 明确 key、顺序、单位、坐标系、时间、相机与缺失字段 | degree→radian、mm→m、四元数顺序、明确时间对齐 | 用补零伪造缺失传感器，或以重新编号掩盖不同步 |
| 4 动作表达适配 | 在同一设备或已知模型下改变可解释的动作表示 | 绝对关节目标与增量；需有 FK/IK 与参考系才处理末端表示 | 任何 action 向量都能靠重排适配 |
| 5 跨本体迁移 | 在不同结构、手型或控制能力间重建可行操作 | 双臂夹爪→双臂 Dex3；轮式移动→足式移动 | 这只是一次格式转换、自动保证成功 |
| 6 训练打包 | 满足具体训练后端的数据文件与样本接口 | LeRobot v2/v3、相机 key、历史窗口、动作 chunk、统计量 | 存成 LeRobot 就能供所有策略与设备直接部署 |

有些数据只需其中一两层；界面应展示计划中哪些步骤可以跳过、哪些需要适配器、哪些需要新采集或算法。若跨本体迁移尚未支持，可以把数据登记、检查和预览做好，同时明确“不能用于当前目标设备训练/部署”的原因。

## 四个具体例子

### A 自行采集宇树 G1 Dex3

采集系统已经知道本体、手型、相机和命令来源，所以不需要重新猜测 schema。适配器检查 Unitree JSON 与图片，按已核对顺序构造双臂双手的 state/action，再写目标训练格式。仍需检查名义频率、真实同步、保存完整性和任务标签。普通双臂配置不应丢掉移动信息后却标成“全身搬箱数据”。[R01][R03]

### B 导入相同配置的官方 LeRobot 数据

如果读取器支持它的版本，通常直接读取并建立训练数据视图，不必先还原成 Unitree JSON 再转换回来。仍要核对实际 `info.json`、关节/手指名、动作目标/单位、相机布局、任务和数据覆盖，必要时做版本迁移或 key 映射。结构匹配、语义匹配和任务匹配应分别显示。

LeRobot 存储布局与样本接口参考固定版本文档，实际来源按其元数据验收。[R15]

### C 导入智元 G2 数据用于 G1 项目

AgiBot World 2026 的元数据中还组织了向量子字段解释及任务分段等信息；这与普通宇树原始记录不同。需要先适配其实际容器/schema，保留分段与指令，再检查它的动作是否能映射到目标。不能丢掉原始子字段解释，将一段 flat vector 当成 G1 目标关节角。[R09]

若目标是研究跨本体学习，可以输出保留源本体标识和可用特征的数据视图，接到明确支持该表示的模型。若目标是直接驱动 G1，则必须补齐动作迁移、控制器与任务评价；不能用“两个模型都是人形”放行。

### D 购买一家厂商的 HDF5 或录包

上传/选择交付目录后，根据交付清单校验文件。没有 schema 时先展示可见字段，列出未解决的动作含义、时间、单位、相机和来源本体问题。已是 LeRobot 也不免除这些检查。工作台支持保存待补材料和映射草案；缺少关键说明时，不推断成某个已知厂商模板。

## 数据契约的建议

通用层不固定 28/43 维，而是明确“有语义的特征 + 设备/任务信息 + 时间关系”。下列是设计示意，不是既定数据库或完整标准。

```yaml
source:
  publisher: unitree
  original_robot_profile: unitree/g1/29-dof/dex3/profile-001
  capture_backend: xr_teleoperate
  format: unitree-json
  source_revision: pinned-revision
  use_conditions_ref: source-record

episode:
  id: episode-unique-id
  task_profile: transfer-box-v1
  outcome: unknown
  termination_reason: operator_stop
  parent_episode_id: null

timing:
  nominal_hz: 30
  source_clock: unknown
  host_receive_clock: monotonic
  alignment_method: unverified

observation:
  joint_position:
    names: [explicit-ordered-names]
    unit: rad
    values: measured
  cameras:
    - name: head_left
      calibration_ref: calibration-id-or-unknown
      timestamp_ref: per-stream-or-unknown

action:
  kind: joint_position_target
  names: [explicit-ordered-names]
  unit: rad
  reference_frame: joint_space
  command_time_ref: recorded-or-unknown
  applied_ack_available: false

status:
  schema_check: pending
  semantic_check: pending
  timing_check: unknown
  task_review: pending
```

这是建议新增信息的示意；此前原始采集没有的 Host 时间、命令执行回执或标定不能事后声称已存在。`generated`、`sent`、`accepted`、`applied` 应区分，缺回执就标记未知。关节角与夹爪开合量不一定共用同一单位，实际 profile 应按特征描述。

## 数据质量与人工判读

检查分为结构/完整性、数值/物理边界、时间/传感器、任务/操作质量、来源与使用条件。检查状态至少包括通过、失败、警告、未检查、无法验证，不能将 unknown 当作通过。

通用检查负责文件、shape、有限数值、索引、引用路径等；机器人规则负责关节/工具、控制范围与相机约定；任务规则负责是否抓住、掉落、到达与放稳。没有任务可观测性或可靠评价器时，用人工预览给出结论，不伪造自动成功标注。

用户可以排除失败回合、保留研究用失败数据、切段和补任务文本；操作生成新视图。原始数据保留，筛选原因和修改记录可追踪。训练/验证/测试划分先确定，同源回合及其所有增强变体保持同组；正式泛化测试进一步按场景/采集批次划分。

## 增强应该插在哪里

训练时亮度/色彩增强不必写一套新视频，可直接成为训练配置。相同有效动作的仿真重渲染需要可重建的场景与相机，不仅是换文件格式。改变质量、摩擦、物体位置或路线时要重新仿真、重新判断成功，必要时重新生成动作。

所以增强既可能在导出之前，也可能是训练时的算子；工作台提供能力和插入点，由具体任务模板决定。不能规定所有来源统一先增强、再转换、再训练，也不能把重渲染原数据视为已经完成跨域或 sim-to-real。

## 导出和训练准备的完成条件

导出前展示源/目标特征差异、单位转换、时间处理、缺失项和将被丢弃的信息。导出后用目标训练后端实际读取少量样本，检查图像颜色/形状、state/action 顺序、episode 边界、任务文本和时间窗口，再生成完成清单。

已在目标格式的数据可以以引用视图方式交给训练器，避免复制大视频。归一化统计按训练集合生成或重新核实，不因为数据提供了 stats 就一律信任。模型输出、预处理和反归一化与相同契约一起打包，后续部署再核对目标控制器。
