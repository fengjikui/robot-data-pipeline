# 宇树 智元 银河通用的数据管线适配调研

核查日期：2026 年 10 月 25 日。目的：确定未来工作台应如何隔离差异，并给出接入工作清单。本轮没有三家设备的实机联调，以下“公开资料确认”不等于“本项目已经支持”。来源 R01 至 R16 见 `06_调研来源与证据.md`。

2026-10-26 补充：采集流程本身的可复用操作、操作者输入/动作映射/视频/记录接口方向已单列为 [初步调研](08_跨本体遥操作与采集接口初步调研.md)，包括以后接入自研机械结构的前提，当前不增加多本体实现承诺。

## 先避免三个命名误区

第一，银河通用是 **Galbot / GalaxyGeneralRobotics**；银河动力是 **Galaxea**，不是本次三家之一。第二，宇树 G1、智元历史数据平台中的 AgiBot G1、银河通用 Galbot G1 不能因名字相同而视作同一本体。第三，银河通用发布的 OpenWBT 包含以宇树 G1 为目标的示例，软件发布方和实际控制本体是两个独立维度。[R11]

设备 ID 建议包含厂商、系列、硬件配置和软件配置，例如 `unitree/g1/29-dof/dex3/<profile_revision>`，具体命名规范后续确定。公开数据还应另外记录发布方、原始本体和采集系统，不能只记录 brand=galbot 或 robot=G1。

## 一 宇树 G1 作为首个基线

### 有哪些已知基础

- 固定版本的 `xr_teleoperate` 已有头显输入、相机服务、G1 双臂和不同手部控制、录制及本地 IPC 入口。[R01][R02]
- `unitree_lerobot` 提供 Unitree JSON 到 LeRobot 的具体映射，普通 G1 Dex3 是双臂加双手；转换器不是通用全身导出器。[R03]
- 官方 `unitree_sim_isaaclab` 提供若干本体/手型/任务组合；需要具体场景和接口验收，不是一个通用搬箱场景。[R04]

### 工作台还要补什么

服务模板及依赖检查；Host/PC2 的受控执行与状态回传；只读探测与控制接管区分；IPC 目标状态适配；保存完成事件与回合索引；时间戳与动作语义记录；检查/训练/仿真/部署后端；界面和故障恢复。

这些工作中，SDK、IK 和底层控制已有工具可复用，工作台重点做可靠组织。若目标扩展到抱箱行走，则要增加相应移动状态/指令记录、全身控制模式和任务评价；不能通过普通 Dex3 exporter 自动获得。

## 二 同为宇树但更换型号或选配

固定遥操作源码列出 `G1_29`、`G1_23`、`H1`、`H1_2`、`H2`、`R1_A5` 和 `R1_A7` 等 arm 选择。但转换器 `ROBOT_CONFIGS` 并没有为这些型号自动提供同等完整映射。**支持遥操作不等于支持记录导出、训练、仿真和部署整条链路。** [R01][R03]

| 变化 | 哪些可能复用 | 必须核对或增加的内容 |
| --- | --- | --- |
| G1 29 换 G1 23 | 同 SDK 家族和部分遥操作、服务编排 | 双臂实际关节数/名字/顺序、IK/模型资产、动作向量、导出配置和部署输出 |
| G1 Dex3 换 Dex1 | Host/PC2 管理、任务和回合流程、部分 SDK | 末端类型和维度、手部状态与开合语义、相机布局、模型输入输出、仿真夹爪接触 |
| 外置 Dex1 换内接 Dex1 | 部分夹爪处理和本体通信 | 内接命令路径与模式限制；当前源码不允许 `dex1_internal` 与 `--motion` 同用，不应强行显示可选 |
| G1 换 H1/H1_2/H2 | 厂商工具家族、通用界面与作业管理 | 控制类、机械结构与臂长、手型、消息类型/关节映射、记录 schema、场景和部署后端 |
| G1 换 R1 | 部分官方遥操作入口和工具家族 | A5/A7 选型、控制接口、手部、相机、导出、训练及仿真支持；不能沿用 G1 28 维 |
| 换宇树 Z1 单臂/双臂 | 数据源管理与已有部分导出配置 | 机械臂 SDK/记录器、单/双臂结构、夹爪、固定场景和动作定义，移除不适用的步态功能 |
| 只换相机或安装位置 | 回合与作业管理、可能复用策略结构 | 相机身份、内外参、时间同步、视角和分辨率、特征 key、训练分布与重新评价 |

上表中的“可能复用”是工程划分，不是已验证的二进制兼容承诺。即使只换手型，也可能需要重新采集或训练；同一个已训练 checkpoint 是否能使用必须单独评价。

## 三 智元 AgiBot

### 已确认的资料边界

这里刻意分开三种材料：

| 材料 | 对应什么 | 能支持怎样的结论 |
| --- | --- | --- |
| A2 AimDK 文档 | A2 的机上模块接口、RPC/Channel 等二次开发方式 | 用于设计设备连接、服务/版本与控制能力的适配，不直接证明 G2 的全部接口 |
| AgiBot World 2026 | 发布方说明由 G2 平台采集的真实数据，含自己的数据结构与标注组织 | 用于设计外来数据导入，不代表购买 A2 就能原样复现 G2 数采 |
| GenieSim | 智元公开仿真平台，提供特定机器人/任务、VR 采集与后处理路径 | 可以作为一个独立仿真后端，不能把它当作任意智元真机的相同运行环境 |

A2 v1.2 的公开边界页对底层运控开发有限制；本轮也找到面向 A2 V1.3/V2.0/v2.1 的自定义运控部署说明。因此不能引用旧限制得出“智元永远不开放底层控制”的结论。应按型号、系统/SDK 版本、控制范围和交付条件登记能力。[R05][R06][R07]

### 从 G1 管线改接智元真机需要做什么

1. 换设备后端：以对应 AimDK/交付接口读取状态和下发命令，处理目标模块所在计算单元、通信后端和版本；不复用宇树主题名。
2. 换服务模板：使用智元设备允许的模块管理/部署方式，核实已有系统服务；不套用 PC2 的 teleimager 启动目录。
3. 适配输入：核实目标产品支持的头显/主从/控制器方案、SDK 和控制权限。GenieSim 公开 Pico 路径不证明该真机已支持 Apple Vision Pro。
4. 适配记录：获取厂商原始记录格式、每路时钟、状态/命令和保存完成事件；缺少可用记录器时，基于已开放接口增加记录层。
5. 适配观察/动作：关节与坐标系、移动控制、末端表示和时间窗；状态和目标命令分别保留。
6. 适配仿真：为实际型号准备匹配资产、传感器、场景、控制器和成功条件。
7. 适配部署：区分使用厂商上层运控与替换底层运控；后者是另一条完整训练/部署工程，不作为首期无感替换功能。

### 仿真和公开数据可先接哪一段

固定 GenieSim 源码的 VR 说明提供 ROS 2 数据记录与 rosbag 到 HDF5 的后处理流程，使用 Pico/AIDEA 输入及任务配置。工作台应把“采集后处理”作为明确阶段，接收其成功输出，再接通用数据检查与训练导出。[R08]

A2 v1.2 的轻量 MuJoCo 示例主要用于接口调用验证，说明没有相机/雷达。故这个示例不能直接作为视觉操作策略的完整评估后端；GenieSim 的 G2 场景也不能未经适配替代 A2 场景。[R06][R08]

AgiBot World 2026 导入需处理其数据版本、`field_descriptions`、任务分段和元数据，而不是使用宇树 raw JSON 提取逻辑。具体分层转换见下一份文档。[R09]

### 尚缺材料

选定真机的准确配置与软件版本；遥操作交付包和程序化启停入口；原始数据 schema/导出约定；记录完成状态；可用仿真资产和控制器；目标控制范围的实际权限。本轮没有取得这些产品交付材料，不能列为已接入能力。

## 四 银河通用 Galbot

### 已确认的公开接口

当前固定 GalbotSDK 仓库 README 声明 SDK 1.10.0 与 GBS 1.18 版本对应，提供独立兼容性检查工具。工作台可复用版本检查思路，但必须核实实际部署版本，不把任何 GalbotSDK 都视为互相兼容。[R10]

公开 G1 SDK 文档包含关节/传感器读取、关节及末端控制、控制器启停和导航等能力；其中低频姿态接口与高频命令接口有明确用途差异。已查阅的是文档 1.7.0，函数签名与参数迁移到 1.10.0 时需再次对照其随包文档，不能混用版本。[R12]

Galbot 的 TM01 主从臂说明存在录制、分段、失败标记等操作。但本次没有核实其程序化录制接口、数据包 schema、导出权限与保存完成协议；“有物理录制键”不能证明我们能直接从网页控制它或按 Unitree JSON 解析。[R13]

### 从宇树 G1 改接 Galbot G1 的具体变化

| 层次 | 需要改变的内容 | 不应作出的假设 |
| --- | --- | --- |
| 计算与网络 | 按 Galbot 的计算单元和 SDK 拓扑配置执行位置、连接与版本探测 | PC2、地址、进程名或 DDS 主题与宇树相同 |
| 设备控制 | 调用 Galbot 对应的控制器/关节/末端/移动接口，核对控制权和高频接口 | 只要能调用低频 `set_joint_positions` 就能逐帧执行视觉策略 |
| 遥操作输入 | 先接已有主从方案，或另做并验证 Vision Pro 输入和映射 | OpenWBT 来自 Galbot 组织，就等于其 Galbot 本体已有 Vision Pro 适配 |
| 记录与标签 | 对接 TM01/厂商记录器或自建经过验收的 SDK 记录层；保留成功、失败、分段 | TM01 原始数据等于宇树 JSON 或天然等于 LeRobot |
| 数据契约 | 用实际关节组/工具、传感器身份、单位和时钟；适配图像与状态字段 | Galbot G1 也使用宇树 G1 的 28/43 维结构 |
| 仿真 | 获取准确本体资产、传感器和控制器，再搭建相同任务 | 模型能加载就等于能够评估视觉搬运任务 |
| 部署 | 使用匹配 SDK/系统的推理包装和动作执行器，核实启停及版本 | 复制宇树部署脚本就能使用 |

### 商业与交付边界

SDK 公开概述区分基础/高级接口与需额外解锁的业务能力。工作台管理“自己训练的策略”与“调用厂商现成搬运业务模块”时要使用不同后端和结果标签；调用现成业务功能成功，不等于我们用数据训练出了该能力。[R12]

需要向交付方取得：实际系统/SDK 对应表；原始记录样例与字段说明；可程序化的采集和完成状态；相机/工具标定；模型资产及允许的使用方式；目标控制频率、退出和超时行为。缺资料时可以完成连接层设计，但不能承诺完整数采与训练迁移。

## 五 固定机械臂示例 UFACTORY xArm

为避免抽象停留在“换成机械臂也一样”，补充第四个国内平台作为结构对照。xArm 官方 Python SDK 提供关节反馈和控制等接口，文档也明确涉及毫米以及角度/弧度选项。因此跨设备的单位转换不是可忽略细节。[R14]

换成如 xArm6 加夹爪，设备档案改为单臂/工具/外部相机，启动器对接机械臂控制箱和相机，输入映射可选择经过适配的拖动示教、主从或 XR，动作可以是明确约定的关节目标或末端增量。没有移动底盘时，任务中“走到桌 B”需要改为可达工作空间内放置，或另配移动平台；工作台应提示任务能力不匹配。

需要新的运动学模型、工作空间与限位规则、夹爪语义和接触场景，以及部署控制器；不需要为固定机械臂伪造腿部状态。上层的数据来源、回合管理、质量报告、训练作业和结果页面仍可复用。具体 xArm 型号、工具、固件、控制模式和 XR 适配均待选型后验收。

## 七 以后如何判断一个新设备是否真的接上

每个适配器须提交：设备/版本清单，能力声明，启动/停止副作用，状态与动作契约，一份可检查的原始数据，保存完成的依据，离线回放/仿真/真机各自通过的验收范围。界面同时展示“资料声明能力”和“本项目验收结果”。

最小接入等级可分为：仅有资料 → 本地后端已封装 → 只读连接通过 → 采集通过 → 转换/训练通过 → 匹配场景仿真通过 → 指定范围真机通过。等级允许某一能力单独缺失，例如可以导入该厂商公开数据，但尚不能控制其真机。

不要写未经测试的“仅需改 20%”“两天支持所有型号”或全厂商统一成功率。可靠的复用结论应来自两个不同配置通过同一工作流和契约检查后得到的证据。
