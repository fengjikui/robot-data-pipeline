## 后续讨论怎样避免退回功能菜单

后续以一个完整的搬箱实验作为讨论对象，先弄清目标和最终交付，再沿实际过程检查交接。下列是讨论提纲，不是已确认需求或功能清单：

1. **任务从哪里开始，怎样算完成？** 从提出搬箱目标到获得可解释的训练/评价结果，哪些环节属于产品范围，哪些由设备或现有工具承担？
2. **系统持续管理的对象是什么？** 任务、来源、实际持有数据、回合选择、处理配方、训练输入、模型、评价和失败回流怎样关联？
3. **什么变化应传递到后续步骤？** 改数据选择、转换或增强配方之后，哪些结果仍可复用，哪些需要重新准备或执行？
4. **哪里需要处理交接失败？** 下载、保存、检查、转换或执行失败时，使用者如何知道已完成什么，并继续同一实验？
5. **今天用什么完整故事证明产品价值？** 确定连续用户流程、真实后端和可查看产物后再编码，而不是先挑几个独立按钮。

当前v0.1.2业务能力已按源码核查：本地导入、结构质检、自有JSONL导出与记录；远端下载、官方标准格式处理、增强、训练和部署尚未接入。用户表示已有服务器，SSH别名和规格尚未提供。当前合并稿不把上游公开示范当作本项目闭环实测。
