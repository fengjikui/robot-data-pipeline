# 数据管线工作台：后半部分逐页大纲

成稿更新：本文保留后半部分的初拟大纲。对应页面已制作为整套报告的一部分，含引用的精讲/扩展讲稿见 [逐页阅读稿](07_全稿逐页阅读与演讲稿.md)。下面的初拟时长与制作状态以总稿为准。

更新：2026 年 10 月 26 日。状态：大纲草案，尚未制作 PPT。后半部分建议 7 页，约 6–8 分钟；页码暂用 B1–B7，便于后续与实现进展一起迭代。

前半部分解释现有工具怎样采集、处理、训练和部署，后半部分说明使用这些工具时的具体成本，以及本项目准备怎样组织它们。当前成果、正在开展的实验和设想中的功能要分别表述。

全稿的正文编号、主要问题与初拟画面见 [逐页总纲](00_全稿逐页总纲.md)。B1–B7 对应正文第 17–23 页；逐页详细内容与版式随后交互讨论。

## B1 现有工具链的使用成本

- 采集准备分散：不同设备运行不同服务，需要反复登录、启动和确认状态。
- 数据整理与交接靠人工：外部数据常需重复查找、选目录、归档和确认字段/用途，再交给转换与训练。
- 更换本体影响采集链路：遥操作输入、控制接口、视频与记录服务可能变化；换数据/策略也需核对相应适配范围。

页面形式：用前半部分同一条流程，标出人工操作和配置交接位置。

依据：官方遥操作部署步骤与转换/训练说明 [T01][T02]。这些“不便”是基于工具使用步骤的工程分析，尚未做用户调研或效率测量，不给出未经实测的节省比例。

## B2 我们拟建设的数据管线工作台

- 目标：在一个界面中准备设备与采集，管理外部数据入库和检索复用，并逐步运行处理、训练、评估和部署。
- 首期范围：单人、单台 G1及少量固定训练配方；已有工具通过接口组织，每阶段有按钮，可选自动串联。
- 操作信息：明确当前状态、输入和产出、未满足的条件，以及下一步可以做什么。

页面形式：一张简洁的功能流程示意，注明“规划”，后续有真实界面后替换。

依据：[本项目已确认需求与功能范围](../product/01_产品需求说明.md)。这是本项目方案，页面标注“本项目设计”，不借外部文献将规划功能表述为已验证成果。

## B3 固定任务与本体后的数据使用流程

- 确定目标：以同一个搬箱任务和目标 G1 配置为前提，明确训练用途、配方与观察/动作要求。
- 选择数据：自行遥操作、找开源数据或购买；采购现成数据先拿清单/样本，定制需求先试采，比较覆盖和适配缺项。
- 实际使用：拿到数据后入库、检查筛选、必要适配、训练读取验收，再训练、评价和部署；角色标注在相应步骤，同一人可承担多项工作。

页面形式：顶部固定任务/本体/配方，下面三条数据取得路径汇入同一条使用流程。用角色小注说明谁负责，并标出哪些现有步骤由人工完成、哪些是工作台拟组织的操作。

依据：[任务驱动的选型与采购验收](../product/09_任务驱动的数据选型与采购验收.md)、[外部数据资产库](../product/07_外部数据资产库与使用流程.md)、[G1 服务编排](../product/02_G1一键采集与服务编排.md)，基础资料参考 [T01][T02][T08]。未实现部分标注“规划”。

## B4 数据资产库与按任务选数

- 管什么：来源与版本、任务/技能、原始本体、实际数据范围、观察/动作说明和质量证据。
- 怎样找：先选任务、用途、本体和固定配方，用标签缩小候选，再看兼容差异与缺项；不把相关标签直接当成可训练结论。
- 怎样复用：保存回合视图、采购样本/批次检查与适配证据；重复使用复用产物，关键条件变化再检查。

页面形式：一个简洁例子，展示“来源条目、已入库范围、训练视图”与一次任务选数。只列主要信息，完整字段和枚举放备查。

依据：[本项目独立设计](../product/07_外部数据资产库与使用流程.md)，资料依据为 [Dataset Cards][T07]、[Hub 下载能力][T08]、[LeRobot 元数据][T09]。这是规划功能，外部资料不作为本项目已实现的证明。

## B5 遥操作与采集的本体扩展

- 通用操作：更换本体后，尽量沿用准备环境、预览、启用遥操作、录制回合与结束保存的使用流程。
- 接入思路：将操作者输入、动作映射、本体状态/控制、相机视频与记录后端分别组织；先封装已有工具，按能力启用界面操作。
- 首期与扩展：先做实 G1；机械臂、其他型号/厂家和自研本体按实际需求新增适配并验收。能采到新本体的数据，与旧数据/模型的迁移分别判断。

页面形式：上方一条通用采集流程，下方 G1、机械臂、其他/自研本体的采集后端示意。标明首期目标与扩展方向，讲约 40–60 秒；不展示复杂 API 或已兼容全部设备的列表。

依据：[本项目采集接口初步调研](../product/08_跨本体遥操作与采集接口初步调研.md)、[LeRobot 硬件接入][T10]、[相机接口][T11]和 [宇树遥操作][T01]。三家厂家与机械臂的具体接口差异留备查；通用采集框架属于规划，尚未实现多本体接入。

## B6 当前基础与实施顺序

- 已有基础：设备/源码调研、需求文档、局部数据检查与数值学习原型，以及有记录的有限范围 G1 仿真实验。
- 首轮实现：固定一套 G1 与一个配方，完成图形采集、外部资产基础入库和任务选数，再接训练与匹配场景闭环。
- 后续实施：完成受限真机部署验收，再通过来源、训练与采集后端接口逐项接入新对象，并验证流程复用。

页面形式：“已有基础”和“待实现”分列，配一条简短的实施顺序；演示内容以定稿时核实的实际实验记录替换。

依据：[现有 G1 实验记录](../04_仿真演示与算力计划.md)、[模型指标](../../artifacts/bc_run/metrics.json)、[需求与阶段验收](../product/01_产品需求说明.md)。其他并行实验未在本大纲中汇总，不将其自动视作工作台能力；正式制作前更新成果状态。

## B7 第一版如何验收与后续改进

- 可重复：采集可重跑，外部数据可在库内找回、选数和复用；状态与产物一致，失败能定位恢复。
- 可评价：从数据实际训练并在匹配场景闭环评估，保留成功、失败和中止的完整结果。
- 可扩展：先验证一个完整 G1 链路，再用第二个数据来源或设备检验流程复用；把实验发现带回需求和实现。

页面形式：三项具体验收目标，作为后续讨论入口。区分管线运行成功与策略任务成功，不承诺尚未测量的成功率或效率提升。

依据：[本项目成功标准与路线图](../product/01_产品需求说明.md)。验收目标属于计划，未完成前按“拟验收”标注。
