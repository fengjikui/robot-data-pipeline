# v15 后半部内容审阅：围绕 G1 搬箱任务收束方案

审阅范围：v14 物理第20–29页，以及当前产品整体方案文档。本文是内部编辑建议，不作为报告的权威参考资料。数据集事实由专项调研补齐，未在这里虚构候选、训练结果或仿真成功。

## 1. 当前为什么显得臃肿

问题主要是重复，并非每一项都不重要。

- 第20页的接入分支、第22页的采购验证、第25页的适用性，反复讲字段、动作、本体、配方和缺项，观众难以知道每页新增了什么。
- 第23页直到后半段才转入平台价值，而且“获取、处理、使用、迭代”的分类仍较抽象，没有直接落到一次采集、一次选数、一次实验的具体麻烦。
- 第24页整体方案、第26页界面、第27页后端架构共同说明一个平台，但主报告未突出使用者究竟点哪些按钮、得到哪些产物；单独讲架构扩展削弱当前 G1 场景。
- 第28页把首个完整 G1 闭环拆到 M1–M3，容易让人理解为第一阶段只做采集。用户现在明确要求：第一阶段就以特定本体、特定搬箱任务，同时满足遥操作和外部数据的实际使用需求。
- 第29页“3次会话、5名用户”等细节适合验收方案，不必在主讲页占一整页。台上更应说明每阶段交付什么、用什么证据确认完成。

## 2. 建议的七页结构

保留物理第1–19页，从第20页开始以七页替换原十页。外部数据两页，平台问题与方案五页。全稿从29张减为26张。下面每页最多三组主内容，详细字段、接口和验收数字留在讲稿及附带文档。

### 第20页：搬箱数据怎么找：先看实际候选，再决定下载范围

**一句主结论：我们要找的是能补当前搬箱技能的数据，并在下载整库前确认实际内容。**

三组主内容：

1. **两个或三个实际候选。** 放真实名称、官方链接、小段任务示例、格式和本体/手型；一列明确它覆盖抓取、携带或放置中的哪部分。候选必须核实，不凭名字中的 box 宣称是完整搬箱。
2. **大集合内找子集。** 任务/本体/动作筛选，查看代表回合，选定回合列表；显示下载范围和已有缓存。按来源实际支持的回合或分片粒度下载，不能把文件名过滤等同于任意回合过滤。
3. **接回共同流程。** 匹配的训练格式直接做检查与读取验收；有已知差异则应用固定转换；缺少移动命令、关键视角或本体对应关系时，形成补采/专项适配待办。

讲述顺序：先指向一个真实目录或任务样例，再比较候选差别，最后说明平台如何减少找数据和搬目录的工作。第19页已讲格式，本页不再重列 JSON/HDF5/RLDS 的百科式分类。

建议版面：左侧候选对照占约三分之二，右侧竖向“筛选—预览—选范围—下载/复用”四步。只展示已核实的具体字段与阶段覆盖。

### 第21页：采购搬箱数据：需求落到交付样本和验收任务

**一句主结论：先约定一批样本怎样在我们的 G1 配方中使用，再谈整批数量和价格。**

三组主内容：

1. **任务与采集范围。** G1 的准确配置与手型；桌A取箱、抱持移动、桌B放置的阶段覆盖；箱体尺寸/重量、桌高、路径等由甲方填定，不编造通用门槛。
2. **可训练交付。** 同步图像、实际状态和实际下发目标；腰腿/机身速度按控制方案记录；字段/单位/频率、相机与标定、原始包和可读训练表示、用途条件。
3. **小样先验收，再分批。** 抽看回合、实际加载、必要转换、匹配场景试训和闭环评价；把合格条件、补交材料、整改责任及后续批次规则写入交付约定。

讲述顺序：用“买一些搬箱数据”与一张具体交付单作对照，台上只讲这三组。有效回合数量、覆盖矩阵、成功/失败分布、许可细项与详细采购检查表放讲稿。

建议版面：三列“我们提什么 / 对方交什么 / 用什么证明”。本项目建议不列为权威来源；若需要引用，只引用实际用到的官方字段说明或数据说明规范。

### 第22页：平台要解决的三个问题

**一句主结论：平台要让一次采集能顺利启动、合适数据能迅速选到、一次实验能继续和复用。**

三组主内容，每组必须是“具体麻烦 + 平台行为”：

1. **步骤繁琐。** 多设备、多服务、多脚本，重复配置且失败后难定位；保存 G1 设备与任务配方，按真实状态编排，提供阶段按钮和从失败节点继续。
2. **数据难找。** 数据集很大、任务混杂，不知道该下载哪部分；按任务和已支持本体检索，预览回合、选范围下载，显示已有数据与需转换内容。
3. **数据难复用。** 文件、处理结果和模型分散，接手人需要重查；把来源版本、选定回合、处理配方、模型和评价绑定，可直接找回和再次使用。

讲述顺序：用用户已经理解的前半流程来点出痛点，再用下一页回答如何实现。避免“行业只有命令行”“平台节省某百分比”等未经比较或计时的结论。

建议版面：三行，每行左侧是一次具体工作中的麻烦，右侧是使用者将看到的操作；不再按抽象的“获取/处理/使用/迭代”分四栏。

### 第23页：整体方案：两类数据入口，共用七个阶段

**一句主结论：同一个任务工作区承接自采和外部数据，统一组织后续执行与结果。**

三组主内容：

1. **同一任务上下文。** G1配置、搬箱范围、模型配方和本轮成功判据；入口分别是遥操作采集、公开/商业数据导入。
2. **七阶段主线。** 数据获取（采集/导入）、质量检查、必要转换、可选增强、模型训练、仿真测试、真机部署。增强可在训练加载时执行；已有合适训练格式的数据可跳过重复转换。
3. **统一操作体验。** 每阶段可点击，也可串联；看到输入、当前状态、输出、日志和恢复入口。部署与设备启用按实际后端和现场步骤执行，界面显示真实条件。

讲述顺序：先讲任务上下文，再展示两条入口合流，最后沿七阶段走一次。不要再次完整解释每个阶段的技术原理，前半已经讲清楚了。

建议版面：两条短入口合流到七阶段横向/折行流程；底部仅一行“输入可复用，成功产物保留，失败阶段可重试”。交互原型保留离线链接即可，取消一整页截图讲解。

### 第24页：首期验证：用搬箱任务走一遍实际链路

**一句主结论：第一阶段用一个确定的 G1 配置和一个确定配方，验证自采与外部数据两条入口都能走到真实使用。**

三组主内容：

1. **固定任务。** 明确 G1 手型、箱体、桌位、路径和第一条训练配方；任务拆成取箱、携带移动和放箱。受限抓放可以先验证，但最终总目标始终保留。
2. **走两条输入。** 自采：预检、启动遥操作、录回合并入库。外部：真实候选、元数据筛选、代表回合查看、按范围下载、必要转换。两者共用质检、增强配方、训练、仿真与产物管理。
3. **留下可检查证据。** 来源与回合清单、可读取训练数据、真实训练模型、闭环评价日志/视频；进入真机后另存实际执行结果。缺少全身覆盖时明确补采和控制接入任务。

讲述顺序：从真实候选和可执行入口讲到实际输出，而不是再次给出一串理论要求。本页应标“验证计划”或“已实测范围”，依据实际进展选择，不能混写。

特别提醒：

- 找到同为 G1、名称含箱子的数据，不等于已有完整抱箱移动轨迹，也不等于手型和动作契约匹配。
- 如果本轮只能完成机械臂代理场景或固定机身抓放，明确标注其用于验证数据管线的哪一段，不能称为 G1 连续搬箱成功。
- 用户希望“找一个效果好的来试”，应落实为先复现匹配官方基线、定义评价条件、留出真实闭环结果；不要预先承诺某个数据集效果好。
- 新转换方法放在真实阻断案例后解释：已有映射覆盖不了时才进入独立适配工作，给出输入/输出定义、样本测试与物理/任务验证。首期不以通用跨本体转换为完成前提。

### 第25页：分阶段实现：先完成 G1 搬箱，再扩大复用范围

**一句主结论：第一阶段交付特定场景的可用闭环，后续阶段扩大可复用数据和支持范围。**

三组主内容，对应三个交付阶段：

1. **S1：G1 搬箱闭环。** 同时包含遥操作与有限开源来源接入、阶段执行、一个配方的训练和匹配仿真、真机分段验证。交付可复跑的任务包和评价证据。内部可按“数据链路—受限抓放—携带行走”逐步联调，主线不再把第一阶段等同于只做采集。
2. **S2：数据与方法复用。** 扩展已验证来源、增强配方与少量模型；针对实际缺口研发转换/重定向。交付新增适配的样本、测试、可复用配置和任务评价，避免只交一个抽象接口。
3. **S3：企业数据规模化。** 完善跨任务检索、共享、存储生命周期与训练加载效率，再按实际采购计划增加本体。交付检索和加载的实际指标、复用记录，以及每个新组合的验收结果。

讲述顺序：当前基础原型一句话带过，然后沿三个阶段说清“用户能完成什么、留下什么证据”。当前 v0.1.2 仍只完成本地导入、结构质检、自有 JSONL 与记录，不能当作 S1 已经完成。

编号建议：本轮报告用 S1–S3 表示用户交付阶段，避免继续使用旧 M1–M4 引发含义冲突。S1 大致覆盖旧 M1–M3，实施文档中的技术工作包仍可细分，不必在主讲页展开。

### 第26页：企业数据仓库：让别人找得到，也让训练读得快

**一句主结论：把可检索的说明、真实数据文件和训练选数分开管理，重复使用时只取需要的内容。**

三组主内容：

1. **找得到：目录与索引。** 搜索任务、技能、本体/手型、模态、动作表达和质量结论；保留来源、版本与实际持有范围。S1 已保存必要字段，规模化阶段完善跨项目检索与权限。
2. **能复用：原始资产与数据视图。** 大文件放文件/对象存储，原始数据保留，派生记录母体与配方；一次训练冻结回合列表和划分，通过引用复用，减少整库重复复制。
3. **读得快：训练侧组织。** 根据实际任务做分片、就近缓存、预取和并行加载；对真实格式测查找耗时、首批次时间与持续吞吐，按瓶颈优化，不默认强制全部转为一种格式。

讲述顺序：用“同事下个月再做搬箱”作为结尾场景：库内筛回合、复用已有适配、启动训练，数据在训练机附近按需加载。字段明细、底层存储选型、权限和成本策略移到设计文档。

建议版面：上层目录索引，中层原始/派生资产与数据视图，下层训练缓存/加载器。避免把“所有视频存进关系数据库”画成数据库方案。

## 4. 最后内容校验

1. 观众看完第22–23页，应能用一句话说明平台解决什么、使用者如何操作。
2. 第20页必须能指向真实候选与实际回合/字段；第24页必须说明实测完成范围或明确为计划。
3. 首期必须同时包含 G1 遥操作和至少一个经过验证的外部来源路径，不能把外部数据推迟到规模化阶段。
4. 每阶段展示“能完成的任务 + 可核查产物”，避免只列模块名或功能清单。
5. 对外部数据只提出一次必要差异判断，不在多页重复全部兼容性清单。
6. 原始资产、子集视图、训练配方和评价结果在方案中关联；完整数据仓库不必成为首期开发前置条件。
