## 2. 转换：原始 JSON/JPG → LeRobot

从宇树适配仓库根目录执行：

```bash
export HF_LEROBOT_HOME="$PWD/datasets/lerobot"
python unitree_lerobot/utils/convert_unitree_json_to_lerobot.py \
  --raw-dir datasets/raw \
  --repo-id local/g1_box_v1 \
  --robot-type Unitree_G1_Dex3 \
  --mode video \
  --no-push-to-hub \
  --dataset-config.image-writer-processes 1 \
  --dataset-config.image-writer-threads 1
```

| 参数 | 含义与注意事项 |
| --- | --- |
| `--raw-dir` | 包含原始回合目录的根目录，不是单个 data.json。 |
| `--repo-id` | 数据标识与相对输出路径；输出在 `HF_LEROBOT_HOME/repo_id`。没有独立的 `--output-dir` 参数。 |
| `--robot-type` | 选择已定义的关节、手部与相机配置；此例为 G1 + Dex3。不是选择训练模型。 |
| `--mode video` / `image` | 图像保存为视频或图片。 |
| `--no-push-to-hub` | 本地转换，不上传；上游默认不上传。 |
| `--dataset-config.image-writer-processes` / `threads` | 图像写入并发；此例各 1，为保守示例值。 |

**重要的实际行为：**固定转换器会删除同 repo-id 的既有输出目录后重建，所以使用新标识，工作台接入时应先检查冲突。该版转换器写死名义 fps=30，须核对来源实际频率；不能用转换命令修复采集丢失的时序。标准 G1 Dex3 配方只读取双臂双手，各得到 28 维 state/action，不读取 body。

## 3. 增强：预览与训练执行是两个入口

### 3.1 官方预览工具

在匹配版本的 LeRobot 环境中执行；保持同一 `HF_LEROBOT_HOME`。工具读取该 repo-id 的默认数据位置：

```bash
lerobot-imgtransform-viz \
  --repo_id=local/g1_box_v1 \
  --episodes='[0]' \
  --image_transforms.enable=true
```

真实脚本：`src/lerobot/scripts/lerobot_imgtransform_viz.py`。也可用 `python` 调用该脚本。

| 参数 | 含义 |
| --- | --- |
| `--repo_id` | 要预览的数据标识，注意此工具用下划线。 |
| `--episodes='[0]'` | 选择回合；本版实际上只取所选第一个回合。 |
| `--image_transforms.enable` | 打开预览变换，不带 `dataset.` 前缀。 |
| `--image_transforms.max_num_transforms` | 每次最多组合多少种变换。 |
| `--image_transforms.random_order` | 是否随机排列变换顺序。 |
| `--image_transforms.tfs` | 完整 JSON 变换候选映射，见下方保守试验配方。 |

该固定版本只预览**第一相机的第一帧**，默认保存在 `outputs/image_transforms/<repo最后一段>/`。不要把 Python 函数形参 `output_dir/n_examples` 当成该版 DatasetConfig CLI 参数。该脚本没有把 `cfg.root` 传入数据集，不能据此承诺任意 `--root` 路径可用。工作台应补充多回合、多相机、首中末与接触阶段的审核。

### 3.2 训练时真正应用增强

LeRobot 在读取图像或解码视频帧时变换，不必先离线改写整段 MP4。固定版本默认候选含亮度、对比度、色相、饱和度、锐度和随机仿射。以下示例显式替换映射，只试轻量亮度/对比度，各 `[0.9,1.1]`：

```bash
lerobot-train \
  --dataset.repo_id=local/g1_box_v1 \
  --policy.type=act --policy.device=cuda --policy.push_to_hub=false \
  --dataset.image_transforms.enable=true \
  --dataset.image_transforms.max_num_transforms=2 \
  --dataset.image_transforms.random_order=false \
  --dataset.image_transforms.tfs='{"brightness":{"weight":1.0,"type":"ColorJitter","kwargs":{"brightness":[0.9,1.1]}},"contrast":{"weight":1.0,"type":"ColorJitter","kwargs":{"contrast":[0.9,1.1]}}}' \
  --batch_size=8 --steps=10000 --num_workers=1 --seed=42 \
  --wandb.enable=false --output_dir=outputs/g1_box_act_aug
```

对预览工具使用同一配方时，去掉上述三个增强参数的 `dataset.` 前缀即可。区间是工程起始试验建议，不是已验证的 G1 最优值。仅开默认 enable 的示例用于理解入口，正式训练应显式指定经审核的配方。

可自写 `LeRobotDataset(image_transforms=callable)`，或扩展变换工厂/训练数据读取路径。固定版工厂只支持 `Identity/ColorJitter/SharpnessJitter/RandomAffine`；噪声、模糊、压缩、gamma、色温等不能凭空填写不支持的 type。新版本接口另行验证。

增强审批建议：按母回合先划分训练/评价 → 预览和规则/Agent 初筛 → 人审新配方与疑点 → 相同预算闭环对照 → 批准或回退。在线变换也要保存实现版本、参数和种子；不同相机/时序的一致性按实际物理扰动设计。没有任何一种增强可直接保证搬箱成功率提升。

### 3.3 仿真轨迹增强的真实入口

Isaac Lab **v2.3.2** 示例，需要先完成匹配任务的录制和标注，输入是 annotated HDF5：

```bash
./isaaclab.sh -p scripts/imitation_learning/isaaclab_mimic/generate_dataset.py \
  --device cpu --enable_cameras --num_envs 1 \
  --generation_num_trials 10 \
  --input_file datasets/annotated_dataset.hdf5 \
  --output_file datasets/generated_dataset_small.hdf5
```

`--device` 是仿真计算设备选项，不表示 Mac 或没有 GPU/Isaac Sim 环境就能运行；该示例也不接收任意 Unitree JSON。物理参数/初始状态变化后要重新执行轨迹、记录并筛选成功结果。

## 4. 训练：已有统一入口，选策略和配方

真实入口：`lerobot-train`，对应 `src/lerobot/scripts/lerobot_train.py`。不加增强的 ACT 基线示例：

```bash
lerobot-train \
  --dataset.repo_id=local/g1_box_v1 \
  --policy.type=act --policy.device=cuda --policy.push_to_hub=false \
  --batch_size=8 --steps=10000 --num_workers=1 --seed=42 \
  --wandb.enable=false --output_dir=outputs/g1_box_act_baseline
```

| 参数/选择 | 实际用途 |
| --- | --- |
| `--dataset.repo_id` | 数据集标识。 |
| `--dataset.root` | 可选，数据实际本地目录；省略时按缓存/仓库查找。训练器支持这一项，不代表预览工具也正确转发它。 |
| `--policy.type` | 已集成的 `act/diffusion/pi0/pi05/groot`。无需在报告中把现成集成重新当成待开发的模型接口。 |
| ACT | 调 `--policy.chunk_size`、`--policy.n_action_steps` 等实际配方字段。 |
| Diffusion | 调 `--policy.n_obs_steps`、`--policy.horizon`、`--policy.n_action_steps` 等。 |
| π0 / π0.5 / GR00T | 依对应现成配置指定检查点、训练模块、精度、资源；并非所有模型共用完全相同的配置字段。 |
| `--policy.pretrained_path` | 指定已有权重；官方 π0.5 示例为 `lerobot/pi05_base`。 |
| `--policy.device` | 本示例为 CUDA；需与实际机器和策略支持一致。 |
| `--policy.push_to_hub=false` | 不将模型上传 Hub。 |
| `--batch_size/steps/num_workers/seed` | 批大小、训练步数、读取并发与种子。示例不是训练预算或效果承诺。 |
| `--output_dir/job_name/wandb.enable` | 产物目录、任务名和实验记录选项。 |

同一份语义匹配的 LeRobot 数据可交给这些已集成策略；运行前仍需数据质检、模型所需相机/语言/动作检查，以及各自依赖和权重准备。缺失的腰腿/移动命令须从采集与转换补齐，不能用 `--policy.type` 或补零解决。
